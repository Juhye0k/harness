# 최소 개발 하네스

하네스는 별도 모델이 아니라 AI와 사람이 같은 절차로 수정·실행·검증하는 환경이다.

## 연결 구조

`AGENTS.md → 코드 변경 → scripts/verify.py → 실패 로그 → 수정 → GitHub CI → 사람의 검토`

| 요소 | 파일·설정 | 현재 역할 |
|---|---|---|
| 지침 | AGENTS.md | 범위, 계층, 완료 조건 |
| 환경 | pyproject.toml, uv.lock, .python-version | 의존성·Python 버전 재현 |
| 실행 | Dockerfile, compose.yaml | API·DB·브로커·워커 분리 |
| 검사 | tests/, scripts/verify.py | 건강 상태·실패 응답·정보 노출·실제 작업 소비 |
| 자동화 | .github/workflows/ci.yml | 기본 검사·통합 검사·이미지 빌드 |
| 리뷰 | PR template, 아래 기준 | 사람이 판단할 근거 수집 |
| 권한 | 에이전트 실행 환경, GitHub permissions | 문서가 아닌 실제 실행 제한 |

## AI 코드 리뷰 기준

1. 요청 범위를 넘어 기능을 만들었는가?
2. DB·Redis 장애를 성공으로 표시하거나 비밀값을 로그·응답에 노출하는가?
3. 모듈 import만으로 외부 연결이나 작업 실행이 발생하는가?
4. 대기열에 큰 영상 데이터를 넣거나 API 요청에서 긴 처리를 직접 실행하는가?
5. 실패·중복 실행을 고려하지 않은 재시도가 있는가?
6. 테스트가 실제 요구를 검사하는가? 검사 생략을 통과로 표현하지 않았는가?

리뷰 출력은 `파일:위치 / 발생 조건 / 영향 / 수정 제안 / 검증 방법` 형식으로 작성한다. 자동 AI 리뷰 서비스는 아직 연결하지 않았다. 먼저 현재 에이전트에 위 기준으로 변경 diff 검토를 요청한다.

## 완료 조건

- 기본 검사 통과
- DB·워커 변경 시 통합 검사 통과 또는 미실행 이유 명시
- 구현 범위와 문서·다이어그램 일치
- 커밋 전 비밀값·영상·개인 자료 제외 확인
- CI 성공을 실제 확인한 경우에만 성공으로 보고

## 제한

Compose는 로컬 환경이고 고가용성·운영 보안 구성이 아니다. 현재 작업 멱등성, outbox, 자동 복구, GPU, 모델 품질 평가는 구현하지 않았다. CI에 배포 권한은 없으며 GitHub 병합 보호 규칙도 별도 설정이 필요하다.
