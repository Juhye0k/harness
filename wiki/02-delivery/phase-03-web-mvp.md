# 3단계 — 샘플 기반 웹 MVP

> 상태: 설계 초안 · 현재 레포 미구현 · 기준일: 2026-11-15 · 유지관리: 프로젝트 개발자

[위키 홈](../README.md) · [카테고리 목차](README.md)

## 목적

실제 AI 분석의 불확실성 없이 사용자가 입력부터 다운로드까지 진행할 수 있는지 확인한다. 기존 별도 화면 프로토타입은 참고 자료이며 이 저장소와 연결되어 있지 않다.

## 사용자 흐름과 책임

| 화면 | 사용자 행동 | 서버 책임 |
|---|---|---|
| 입력 | 파일 선택·생성 조건 입력 | 입력 제한·업로드 정보 검증 |
| 처리 | 대기·진행·실패 확인 | 작업 상태 반환 |
| 후보 | 구간·점수·이유 비교 | 샘플 후보임을 명시한 결과 제공 |
| 편집 | 제목·자막 수정 | 편집 버전 저장·시간 범위 검사 |
| 출력 | 생성·다운로드 | 선택 버전 렌더링·파일 검증·접근 확인 |

## 설계 원칙

- 후보 생성은 샘플 응답으로 대체하되 영상 출력은 단계별로 실제 처리한다.
- 자막 편집 결과는 자동 전사 원본과 구분한다.
- 선택한 후보만 최종 렌더링하고 나머지는 미리보기로 확인한다.
- 화면 새로고침 후에도 저장된 작업 ID로 상태를 다시 확인하도록 설계한다.
- 실패와 대기를 구분한다. 성공 파일이 없는데 다운로드 버튼을 활성화하지 않는다.
- 전체 진행률을 추정하기 어렵다면 거짓 백분율 대신 처리 단계를 표시한다.

## 완료 기준

동일 시나리오로 입력 → 후보 선택 → 자막 수정 → 출력 → 다운로드를 수행한다. 저장한 편집 내용과 출력 자막이 일치해야 한다. 새로고침·실패 응답·중복 버튼 클릭을 검사하고 샘플 표시가 유지되는지 확인한다.

## 구현 전에 정할 항목

파일 제한, 보관 기간, 미리보기 방식, 편집 저장 단위, 인증 도입 시점, 지원 링크 출처. 이 결정은 [미결정 목록](../07-governance/open-decisions.md)에서 추적한다.

SNS 업로드는 계정 연결·토큰 보관·게시 실패 처리가 필요한 별도 기능이다. 이 단계에서 성공처럼 모의 표시하지 않는다.
