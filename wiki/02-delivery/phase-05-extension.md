# 5단계 — 새 기능과 공개 준비

> 상태: 후속 계획 · 기준일: 2026-11-15 · 유지관리: 프로젝트 개발자

## 목적과 진입 조건

기본 사용자 흐름과 실제 추천의 기준 평가를 확보한 뒤, 관찰한 부족함을 개선하는 새 기능을 하나 선택한다. 공개 배포와 기능 차별화는 별도 완료 조건으로 관리한다.

## 새 기능 후보 — 아직 선택하지 않음

| 후보 | 해결하려는 문제 | 확인할 효과 |
|---|---|---|
| 추천 점수 설명·선호 조정 | 추천 근거가 불투명 | 후보 선택 시간·선택 결과 변화 |
| 사건·발화 경계 보정 | 중요한 문맥이 잘림 | 문맥 완결성·수동 구간 수정량 |
| 장르별 점수 설정 | 장르에 따라 신호 의미가 다름 | 장르별 기준 대비 품질 |

후보는 예시이며 구현 약속이 아니다. 4단계 실패 사례에서 실제 필요를 확인한 뒤 선택한다.

## 공개 전 점검

- 사용자 인증·프로젝트 소유권 검사
- 영상 입력·처리 분량·비용 한도
- 작업 중복·중단·재시도와 장애 안내
- 비공개 파일 접근·보존·삭제 정책
- DB 백업과 복구 검증, 운영 로그의 비밀정보 제외
- API와 워커의 자원 분리·상태 관측

배포 대상·월 예산은 아직 정하지 않았다. 공개 GitHub 저장소와 공개 서비스 운영은 서로 다르다.

## 결과 발표 산출물

1. 문제와 사용자 시나리오
2. 참고 제품 대비 재현 범위와 같은 입력의 결과 비교
3. 새 기능 전후 평가와 실패 사례
4. 실제 아키텍처와 비용·처리 시간
5. AI 코딩 과정에서 발생한 실수, 이를 잡도록 개선한 하네스
6. 실행 가능한 시연과 남은 제한

SNS 게시를 선택하면 계정 연동·토큰 보관·게시 확인·실패 복구를 별도 설계 문서로 추가한다.
