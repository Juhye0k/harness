[위키 홈](../README.md) · [카테고리 목차](README.md)

## 목적과 진입 조건

개발 기반이 실행되는 상태에서 고정 샘플 영상의 지정 구간을 정확히 추출한다. AI를 연결하기 전에 입력·출력과 실패 조건을 확정한다.

## 학습할 내용

| 개념 | 이번 구현과의 연결 |
|---|---|
| 컨테이너와 코덱 | 파일 확장자만으로 재생 가능성을 판단하지 않음 |
| 영상·음성 트랙 | 음성이 없는 입력을 허용할지 별도 정책 필요 |
| 해상도·화면 비율 | 세로 변환 시 크롭과 여백의 차이 |
| 프레임·타임스탬프 | 구간 경계와 출력 길이 오차 |
| 키프레임·재인코딩 | 빠른 복사와 정확한 구간 추출의 절충 |
| SRT·VTT | 자막의 시작·종료 시간을 클립 기준으로 변환 |

## 첫 구현 계약 제안

- 입력: 고정 샘플 파일, 시작 시간, 10초 길이.
- 출력: 별도 경로의 영상과 검사 결과. 원본을 덮어쓰지 않는다.
- 시작 시간이 음수이거나 원본 범위를 넘으면 명시적으로 실패한다.
- 길이 허용 오차·음성 보존 정책은 샘플 인코딩 결과를 측정한 뒤 확정한다.

처음에는 일반 Python 함수와 FFmpeg adapter로 검증한다. 이후 그 함수를 Celery 업무 작업에 연결한다. 새 프레임워크를 추가하지 않는다.

## 작업 관리 설계

작업 상태와 메시지 전달은 [데이터·작업 모델 초안](../03-architecture/data-and-jobs.md)을 따른다. 특히 DB 기록 후 발행 실패, 중복 전달, 워커 중단을 어떻게 처리할지 구현 전에 결정한다. 현재 진단 작업의 ACK·시간 제한을 그대로 복사하지 않는다.

## 완료 기준

1. 정상 샘플에서 출력 길이와 필수 트랙을 검사한다.
2. 잘못된 구간·존재하지 않는 파일·도구 실패를 재현하고 오류를 확인한다.
3. API의 작업 번호와 워커 실행 결과를 연결한다.
4. 중복 요청·워커 중단 상황에서 정한 정책이 검사로 확인된다.
5. 실행 명령·설정·입력 ID·출력 검사를 기록한다.

영상 링크 수집·실제 AI 추천은 이 단계의 완료 조건이 아니다.
