## 목적과 진입 조건

개발 기반이 실행되는 상태에서 고정 샘플 영상의 지정 구간을 정확히 추출한다. AI를 연결하기 전에 입력·출력과 실패 조건을 확정한다.

## 학습할 내용

| 개념 | 이번 구현과의 연결 |
|---|---|
| 컨테이너와 코덱 | 파일 확장자만으로 재생 가능성을 판단하지 않음 |
| 영상·음성 트랙 | 음성이 없는 입력을 허용할지 별도 정책 필요 |
| 해상도·화면 비율 | 세로 변환 시 크롭과 여백의 차이 |
| 프레임·타임스탬프 | 구간 경계와 출력 길이 오차 |
| 키프레임·재인코딩 | 빠른 복사와 정확한 구간 추출의 절충 |
| SRT·VTT | 자막의 시작·종료 시간을 클립 기준으로 변환 |

## 첫 구현 계약 — VIDEO-001

- 입력: 공개 YouTube 단일 영상 또는 MP4 직접 링크, 시작 시간, 10초 길이. 고정 합성 샘플은 자동 검사에 사용한다.
- 출력: 별도 경로의 영상과 검사 결과. 원본을 덮어쓰지 않는다.
- 시작 시간이 음수이거나 원본 범위를 넘으면 명시적으로 실패한다.
- 길이 허용 오차는 ±0.1초, 음성이 있으면 첫 음성 트랙을 유지하며 무음은 허용한다. 실제 합성 샘플과 공개 영상으로 검증한다.

일반 Python 서비스와 FFmpeg adapter를 CLI에서 호출한다. 계약·오류·설치·실행 순서는 [영상 추출 안내](../05-development/video-extraction.md)를 기준으로 한다. VIDEO-002에서 그 함수를 Celery 업무 작업에 연결했다. 새 프레임워크를 추가하지 않는다.

## 작업 관리 설계

작업 상태·발행·조건부 선점은 [데이터·작업 모델](../03-architecture/data-and-jobs.md)을 따른다. [ADR-003](../04-decisions/adr-003-redis-celery.md)에 Celery 선택과 복구 정책을, [실행 안내](../05-development/async-video-jobs.md)에 접수·다운로드·관리자 중단 처리를 기록한다.

## 완료 기준

1. 정상 샘플에서 출력 길이와 필수 트랙을 검사한다.
2. 잘못된 구간·존재하지 않는 파일·도구 실패를 재현하고 오류를 확인한다.
3. API의 작업 번호와 워커 실행 결과를 연결한다.
4. 중복 요청·워커 중단 상황에서 정한 정책이 검사로 확인된다.
5. 실행 명령·설정·입력 ID·출력 검사를 기록한다.

사용자 요청으로 첫 입력을 로컬 파일에서 링크로 변경했다. 현재 CLI와 API·워커 상태 연결, 중복 선점 방지, 수동 중단 처리 계약을 구현했다. 자동 복구·실제 프로세스 강제 종료 실험은 완료 근거에 포함하지 않는다. 실제 AI 추천은 이 단계의 완료 조건이 아니다.
