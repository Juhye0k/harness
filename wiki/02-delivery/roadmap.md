## 단계 운영 원칙

일정은 주 단위 약속보다 **진입 조건과 완료 증거**로 관리한다. 단계 문서를 작성했다고 구현이 끝난 것은 아니다. 현재 승인된 구현은 링크 기반 10초 추출 CLI와 비동기 접수·조회·다운로드 API다. AI·웹 편집은 후속 작업이다.

| 단계 | 질문 | 산출물 | 현재 상태 |
|---|---|---|---|
| [0. 문제·참고 흐름](phase-00-discovery.md) | 무엇을 재현할 것인가? | 범위·비교 시나리오 | 참고 제품 선정, 비교 실험 전 |
| [1. 개발 기반](phase-01-foundation.md) | 같은 방법으로 실행·검증할 수 있는가? | 구조·하네스·CI | 초기 설정 구현 및 CI 확인 |
| [2. 영상·작업 처리](phase-02-video-jobs.md) | 작은 영상을 정확히 처리할 수 있는가? | 결정적 추출·작업 상태·복구 설계 | CLI·비동기 API 로컬 검증 완료, 자동 복구 제외 |

## 의존 관계

`0 → 1 → 2 → 3 → 4 → 5`

영상 기초 학습은 2단계에서 실제 추출 실험과 함께 수행한다. 3단계는 실제 AI 없이도 사용자 흐름을 검증한다. 4단계에서 같은 데이터 형식으로 샘플 분석기를 실제 분석기로 교체한다.

현재 개발 환경을 이미 만들었으므로, 시작 시점의 학습 순서와 완전히 같을 필요는 없다. 다음 기능 개발은 2단계의 작은 입력·출력 계약부터 진행한다.

## 단계 종료 기록

각 단계 완료 시 다음을 [현황 기록](../07-governance/status.md)에 남긴다.

- 검증한 커밋과 실행 명령
- 입력 데이터의 식별자와 설정 버전
- 통과·실패 결과와 재현 방법
- 남은 제한, 다음 단계의 선행 조건

측정 없는 완료 선언, 미실행 검사의 통과 처리, 샘플 응답을 실제 AI 결과로 소개하는 것을 금지한다.
