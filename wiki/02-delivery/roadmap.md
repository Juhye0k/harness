# 단계별 실행 계획

> 개발 단계는 일정 약속보다 진입 조건과 검증 증거로 관리합니다. 초기 계획부터 현재 구현까지의 관계와 실제 품질·운영 검증으로 남은 일을 안내합니다.

**기능을 하나씩 연결하는 단계는 마쳤고, 이제 실제 영상으로 전체 흐름과 품질을 검증한다.** 각 단계는 날짜보다 ‘무엇을 확인하면 끝나는가’를 기준으로 진행한다.


[위키 홈](../README.md) · [실행 계획 목차](README.md)

## 지금 진행할 순서

| 순서 | 할 일 | 이 단계가 필요한 이유 | 완료 증거 |
|---|---|---|---|
| 1 | 변경을 통합하고 main에 반영 | 검증할 코드 버전을 고정하기 위해 | PR·정확한 커밋의 CI 결과 |
| 2 | 최신 실행 환경 준비 | 코드·DB·워커가 같은 버전으로 동작해야 하므로 | 원본 보존·DB 구조·상태 API·실행 코드 확인 |
| 3 | 같은 실제 영상으로 입력부터 다운로드까지 수행 | 시험용 응답에서 보이지 않던 문제를 찾기 위해 | 입력·추천·편집 버전·출력 파일을 연결한 기록 |
| 4 | 사람이 추천·자막 품질 평가 | 처리 성공만으로 쓸 만한 숏폼인지 알 수 없으므로 | 후보 채택·거절·수정 이유, 원음 확인 결과 |
| 5 | 발견한 실패를 하네스에 반영 | 같은 문제가 다음 변경에서 재발하지 않도록 | 재현 검사·제품 수정·재검사 |
| 6 | 실제 게시와 운영 준비 | 계정·파일·공개 범위와 비용을 확인하기 위해 | 승인한 영상의 게시 결과·운영 점검 |

초기 제품 통합은 [PR #8](https://github.com/Juhye0k/short-form/pull/8), 자막 편집·출력 개선은 [PR #15](https://github.com/Juhye0k/short-form/pull/15)로 반영됐다. 11월 19일에는 main과 DB 구조를 맞춘 개발 서비스, 기존 자료 보존을 확인했다. 다음은 같은 영상의 미검수 초안 저장과 사람의 원음 확인, 최종 파일 검사다. [재개 기록](../05-development/harness/records/2026-11-19-flow-resume.md)에서 완료와 대기를 구분하고, 단계별 최신 결과는 [현재 현황](../07-governance/status.md)에 모은다.

## 다음 기능을 늘리는 기준

먼저 같은 영상의 품질을 평가하고 부족한 요소를 고른다. 예를 들어 발화만으로 게임·스포츠의 결정적 장면을 찾기 어렵다면 그때 시각·소리 특징을 추가한다. 아직 측정하지 않은 가중치·목표 수치·개선율을 먼저 확정하지 않는다.

추천 개선은 [평가·반복 절차](../05-development/recommendation-improvement-loop.md), 자막은 [표시 정책](../05-development/shorts-display-policy.md), 실패 검증은 [실패 경로 검사](../05-development/failure-path-testing.md)를 따른다.
