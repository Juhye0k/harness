# 문제 정의와 프로젝트 목표

> 긴 영상에서 짧은 콘텐츠를 만들 때 가장 번거로운 일은 구간 탐색과 반복 편집입니다. 이 글은 누구의 문제를 해결하려는지, 제품 목표와 개발 과정의 검증 목표를 어떻게 구분하는지 설명합니다.

[위키 홈](../README.md) · [카테고리 목차](README.md)


## 이 프로젝트가 해결할 문제

롱폼 영상에서 숏폼을 만드는 사용자는 원본을 탐색하고, 독립적으로 이해할 수 있는 구간을 고르고, 자막을 정리한 뒤 결과를 출력해야 한다. 후보 탐색과 반복 편집을 줄이되, 최종 선택과 자막 수정은 사용자가 통제할 수 있는 도구를 만든다.

이 문제 설명은 현재의 제품 가설이다. 사용자 인터뷰나 실제 편집 시간 측정으로 검증된 시장 조사 결과는 아니다.

| 대상 | 수행하려는 일 | 현재 가설인 어려움 | 제공할 가치 |
|---|---|---|---|
| 긴 영상을 보유한 개인 제작자 | 짧은 콘텐츠 후보 찾기 | 원본을 반복해서 탐색 | 여러 후보와 구간·추천 이유 제공 |
| 후보를 비교하는 편집자 | 적합한 클립 선택 | 추천 근거가 불명확 | 요소별 점수와 미리보기 |
| 결과를 수정하는 제작자 | 정확한 자막과 영상 출력 | 자동 결과를 다시 편집 | 자막 수정·선택한 버전 출력 |

## 제품 목표와 개발 목표

**제품 목표:** 영상 입력 → 복수 하이라이트 후보 → 추천 근거 확인 → 선택·자막 수정 → 영상 다운로드 흐름을 제공한다. SNS 게시와 추가 편집 기능은 후속 범위다.

**개발 목표:** AI 코딩 에이전트가 수정한 결과를 실행 가능한 검사로 확인하고, 발견된 실패를 회귀 검사와 작업 규칙으로 축적한다. 하네스 구축 경험도 프로젝트 결과물에 포함한다.

좋은 결과의 기준은 기능 개수만이 아니다. 같은 입력으로 결과를 재현하고, 잘못된 구간·자막·파일을 탐지하며, 처리 비용과 실패 원인을 설명할 수 있어야 한다.

## 검증할 성공 지표

| 지표 | 측정 방법 | 현재 상태 |
|---|---|---|
| 후보 탐색 시간 | 같은 원본에서 수동 작업과 도구 사용 시간을 비교 | 기준값·목표값 미정 |
| 후보 유용성 | 상위 K개 중 사람이 사용 가능하다고 판단한 비율 | K와 평가 표본 미정 |
| 자막 수정 부담 | 수정한 글자 비율·수정 시간 기록 | 측정 전 |
| 출력 정확성 | 요청 구간·자막·출력 트랙 자동 검사 | 영상 처리 미구현 |
| 비용·처리 시간 | 입력 영상 1분당 분석 비용과 처리 시간 | 측정 전 |
| 하네스 효과 | 고정 실패 사례를 변경 전후 검사에 적용 | 기초 인프라 검사만 존재 |

수치 목표는 기준 실험 이후 정한다. 아직 측정하지 않은 개선율이나 바이럴 성과를 성과로 기록하지 않는다. 추천 점수는 실제 조회수 확률이 아니다.
