## 참고 제품 선정

OpusClip의 복수 후보 추천, Vrew의 자막 수정 경험을 검토한 뒤, 사용자가 제공한 AlphaCut 사용 흐름을 최종 참고로 삼았다. 입력 설정 → 쇼츠 생성 → 후보 확인 → 편집·다운로드 구조가 원하는 경험에 맞기 때문이다.

근거는 대화에서 제공된 화면 설명과 녹화 자료다. 세 제품을 동일 영상으로 측정한 정량 벤치마크는 아직 없다. 제품 내부 알고리즘이나 현재 요금제를 확인했다는 의미도 아니다. 참고 원본과 개인 자료는 공개 저장소에 포함하지 않는다.

## 기능 범위

| 구분 | 포함할 내용 | 단계 |
|---|---|---|
| 입력 | YouTube·MP4 직접 링크 CLI·비동기 작업 등록 구현, 웹 업로드는 후속 연결 | 2~3 |
| 처리 상태 | 요청 수락·대기·처리·완료·실패 확인 | 2~3 |
| 후보 | 복수 구간·시간·추천 이유·미리보기 | 3은 샘플, 4에서 실제 분석 |
| 편집 | 후보 선택, 제목·자막 수정 | 3 |
| 출력 | 선택한 편집 버전의 영상 다운로드 | 3 |
| 분석 개선 | 음성·영상·텍스트 특징과 점수 결합 | 4 |
| 확장 | 새 기능, 계정 연결 후 SNS 게시 등 | 5에서 선택 |

## 최초 구현에서 제외

- 자동 바이럴 성과 예측, 모든 장르에 대한 동일 품질 보장
- 모든 영상 사이트 링크의 다운로드 지원
- 화자 추적·자동 모자이크·BGM 추천의 동시 구현
- 자체 모델 학습, 상시 GPU 클러스터, Kubernetes
- 사용자의 검토 없이 자동 SNS 게시

샘플 기반 프로토타입을 선택했던 결정을 유지한다. 샘플 후보와 점수에는 샘플임을 표시한다. 실제 분석을 붙여도 모든 화면을 한 번에 바꾸지 않고 동일한 데이터 경계 안에서 교체한다.

## 기본 사용자 시나리오

1. 처리할 영상을 등록한다.
2. 분석을 요청하고 작업 상태를 확인한다.
3. 추천 구간과 이유를 비교한다.
4. 한 후보를 선택해 제목·자막을 수정한다.
5. 최종 영상을 만들고 내려받는다.

재시도·오류 표시·뒤로 돌아오기 또한 사용자 흐름에 포함한다. 화면에서 완료라고 표시하는 시점은 출력 파일 검증과 저장이 끝난 뒤로 설계한다.

## 범위 변경 방법

새 요청은 [미결정 사항](../07-governance/open-decisions.md)에 목적·비용·영향 단계를 기록하고 결정 후 해당 단계 문서를 수정한다. 이미 구현된 것처럼 기능 목록에 먼저 추가하지 않는다.
