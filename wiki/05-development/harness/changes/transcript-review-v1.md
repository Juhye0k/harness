# TR-001: 전사 검수 자동 분류와 판정 저장

> 전사 오류를 자동 확정하지 않고 사람이 확인할 구간을 먼저 찾습니다. 의심 구간 분류와 버전별 판정 저장을 추가한 이유와 검사 범위를 설명합니다.

[위키 홈](../../../README.md) · [개선 기록](README.md)


[검수 계약](../../transcript-review.md)에 따라 추가 AI 호출 없는 규칙·선택 신뢰도, 저장 음성 재생, 버전별 판정과 보고서를 구현했다. 최신 판정만 보관하며 원본 전사·SRT·추천을 수정하지 않는다. 기존 전사는 신뢰도를 복원하지 않고 규칙 검사만 한다.

초기 검사에서 메타데이터가 없는 Groq 응답에 빈 quality가 추가돼 기존 정규화 계약 검사가 실패했다. 유효한 메타데이터만 선택적으로 보존하도록 수정하고 Groq HTTP 대역부터 정규화까지 보존되는 회귀를 보강했다. assertion을 완화하거나 외부 호출을 추가하지 않았다.

기본 검사 251개와 격리 실제 PostgreSQL·Redis·Celery·FFmpeg·Chromium 통합 57개가 통과했다. 동시 판정 저장은 200/409로 한 건만 반영하고 원문 불변·음성 Range·실제 재생·새로고침·실패 시 메모 보존·JSON 다운로드·추가 제공자 호출 없음까지 확인했다. 기존 Starlette/httpx 경고 1개는 남는다. 테스트 전용 컨테이너와 볼륨은 정리하고 로컬 서버에는 마이그레이션과 기능을 반영했다.

실제 기존 전사 한 건은 읽기 전용으로 121개 중 검토 후보 26개와 음성 Range 206 응답을 확인했다. 기존 결과에는 신뢰도가 없어 26개는 표시 규칙 기반 후보이며 실제 오인식 수가 아니다. 원본·식별자·전사 내용·보고서는 공개 문서에 저장하지 않았다. 사람 표본 평가·시간 절감 측정·새 v3 실제 ASR 평가는 아직 수행하지 않았다. 커밋·푸시·Wiki 게시도 수행하지 않았다.
