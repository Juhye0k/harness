# 실제 전사 응답 복구와 SNS 선점 경쟁 수정

> 상태: 로컬 구현·검증 완료 / 원격 게시 전 · 기준일: 2026-11-16 · 작업: TR-001 후속, SNS-006 회귀

## 목적과 완료 기준

사용자가 승인한 같은 한국어 영상으로 전사 검수 흐름을 복구한다. 원본 영상·기존 전사·실패 이력을 유지하고 새 결과의 출처를 기록한다. 유료 모드와 자동 재시도는 추가하지 않는다. 시작 커밋은 `fb9b793d95ce21a819838e18971e3c525c5c43b2`이며 현재 변경은 미커밋이다. 요청은 같은 영상의 실패 해결이다. 코딩 모델의 정확한 실행 식별자와 공급자가 제공하지 않은 비용·사용량은 알 수 없음으로 남긴다.

## 관측과 원인

첫 시도의 HTTP 403은 후속 실제 전사 요청에서 재현되지 않았다. 계정 권한을 변경하지 않았으며, 최초 403의 정확한 원인은 확인되지 않았다. 안전한 진단을 위해 고정 HTTP 상태·허용된 오류 코드·응답 종류만 저장하도록 개선했다. 원시 오류 본문·키는 저장하지 않는다.

후속 실제 응답은 정상 반환됐지만 단어 시간이 원 전사 구간 밖까지 이어지고 원문과 단어 목록에 한 글자 차이가 있었다. 보조 단어 정보를 원문과 정확히 일치시켜야 한다는 기존 검증이 전체 전사를 `MODEL_RESPONSE_INVALID`로 거부했다.

## 제품과 검증 변경

- 기본 전사 데이터의 형식·시간·영상 범위 검증은 유지한다. 보조 단어 정보가 불일치하면 해당 응답의 단어를 사용하지 않고 `UNALIGNED_WORD_TIMESTAMPS`를 표시한다. 원문·구간 시간·신뢰도는 보존한다.
- 신뢰할 수 없는 단어 시간으로 분할하거나 원문을 고치지 않는다. 단어 정보 제한만으로 오인식 우선순위를 올리지 않는다. 자막 길이·읽기 속도 등 별도 문제는 계속 표시한다.
- 보조 정보 오류 테스트는 이제 전체 거부 대신 원문·시각 보존, 단어 제외, 명시적 경고, 외부 호출 1회를 검증한다. 기본 전사 검증 실패 테스트는 유지한다.
- 전체 통합 검사에서 SNS 상태 조회 메시지가 DB 커밋보다 먼저 소비되면 선점을 건너뛰는 경쟁 조건이 발견됐다. ID로 행 잠금을 얻은 후 커밋된 상태·작업 토큰을 검사하도록 수정했다. 발행 성공·발행 실패 롤백 각각의 경쟁 재현 검사를 추가했다. 업로드 재전송·자동 복구는 추가하지 않았다.

## 실제 샘플 복구와 기록

이 후속 작업에서 빈 파일 진단 1회와 실제 전사 요청 2회를 기록했다. 두 번째 실제 요청은 정상 응답을 검증 전에 비공개로 보존하기 위한 명시적 캡처였다. 자동 재시도는 없다. 제공자가 제공하지 않은 비용·사용량은 `null`이며 무료 계정 확인이 실제 비용 측정값을 뜻하지 않는다.

최종 복구는 보존 응답을 수정된 파서로 처리했으며 외부 호출은 없었다. 새 분석과 전사를 별도로 저장하고 `offline_response_replay`, 원본 분석 ID, 응답 SHA-256, `external_call=false`로 출처를 기록했다. 기존 실패 행은 성공으로 바꾸지 않았다. 같은 불변 영상 파일을 참조하며 원본 해시·구간별 원문·시간 보존을 확인했다. 이는 운영자가 수행한 일회성 복구이며 자동 복구 기능이 구현됐다는 의미가 아니다.

결과는 전사 121개, 신뢰도 정보 121개, 검토 대상 26개다. 이번 규칙의 인식 의심 신호는 0개였고 검토 대상은 표시 규칙에 따른 것이다. 정답 전사와 비교하지 않았으므로 정확도나 탐지 재현율을 의미하지 않는다. 단어 정렬 불일치로 표시 자막은 원본 구간 121개를 유지하며 가독성 개선은 미완료다.

원문·음성·응답·검수 JSON·화면 증거는 Git에서 제외한 비공개 평가 폴더에 보관한다. 이 공개용 문서에는 사용자 영상 내용·키·원시 로그를 넣지 않는다.

## 검사와 남은 제한

`uv run python scripts/verify.py`: Ruff·서식·기본 256개·Alembic 오프라인 SQL 통과. 실제 인프라 격리 검사: 최초 56개 통과·SNS 1개 실패 후 원인을 수정해 최종 59개 모두 통과했다. 테스트는 대역을 사용하며 외부 AI·SNS 호출이 없다. 기존 Starlette/httpx 사용 중단 경고 1건은 남아 있다.

실제 복구 결과도 HTTP 전사·검수·자막·SRT 조회 200, 음성 Range 206을 확인했다. Chromium에서 검토 필터 26개·전체 121개·실제 음성 시간 진행·새로고침 시 변경 요청 없음도 확인했다. 원본 성공 분석과 실패 분석 조회는 유지된다.

최초 403의 원인, 실제 한국어 오인식 정확도, 단어 정렬 개선, 실계정 SNS 게시, 운영 자동 복구는 완료하지 않았다. 새 결과를 Celery가 외부 전사부터 다시 처리한 것으로 설명하지 않는다. 수정 코드는 후속 정상 응답에도 적용되지만 복구 완료 후 확인 목적으로 추가 AI 호출은 하지 않았다.
