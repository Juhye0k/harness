# 자막·SNS 변경 통합과 검사 환경 복구

> 개별 작업이 통과해도 자막과 SNS 변경을 합치면 새로운 오류가 생길 수 있습니다. 통합 과정에서 발생한 환경·동시성 문제와 이를 잡은 회귀 검사를 기록합니다.

[위키 홈](../../../README.md) · [개선 기록 목차](README.md)


## 목적과 변경 범위

분리된 자막 분할과 SNS-006 변경을 기존 Groq 전사 변경 위에 통합했다. 브랜치는 `feat/integrate-subtitles-sns`이며 커밋·푸시·Wiki 게시 전이다. 원래 작업 변경은 비공개 로컬 백업에 보존했다. 전사 제공자·무료 모드·word/segment 버전과 YouTube OAuth 설정을 함께 유지하고 공통 화면·문서의 충돌을 해결했다.

## 실행 환경 복구

기존 Docker 엔진은 제한 시간 내 응답하지 않았다. Docker Desktop 프로세스를 재시작한 뒤 엔진 27.0.3 응답을 확인했다. 이미지·개발 볼륨·사용자 데이터를 삭제하지 않았으며 중단된 기존 개발 컨테이너를 다시 시작했다. 통합 검사는 별도 `shortform-merged-check` 프로젝트와 전용 이미지로 실행해 개발 DB·Redis·영상 볼륨과 분리했다.

## 리뷰에서 발견한 결함과 회귀 검사

- SNS 워커는 API 진입점을 거치지 않아 Google HTTP 로그 필터가 설치되지 않았다. 업로드 세션 주소가 INFO 로그에 포함될 수 있어 API·워커 공통의 중복 방지 설치 함수로 변경했다. 독립 Python 프로세스에서 `app.worker`만 불러와 HTTP 대역 요청의 로그를 검사한다.
- 만료된 확인 초안을 편집해 다시 제출해도 같은 요청 번호가 유지됐다. 명시적 초안 편집은 새 번호를 발급하고 응답 유실 재요청은 기존 번호를 유지하도록 수정했다. 실제 SNS JavaScript를 실행해 계정·본문 보존, 진행 중 편집 차단과 함께 검증한다.
- CI에서도 SNS 워커를 명시적으로 시작하도록 검사 명령을 갱신했다. 실제 SNS 제공자나 비밀값을 CI에 추가하지 않았다.

## 검증 근거

- `uv sync --locked` 성공. SNS 토큰 암호화 의존성을 잠금 파일대로 반영했다.
- `uv run python scripts/verify.py`: Ruff·서식·기본 검사 **235개**·Alembic 오프라인 SQL 생성 통과. 통합 56개는 별도 실행했다. 기존 Starlette/httpx 경고와 Windows pytest 캐시 쓰기 경고는 실패와 구분한다.
- 격리 Compose: 실제 PostgreSQL·Redis·Celery·FFmpeg·Chromium 통합 **56개 통과**. 전사/자막/SRT, 후보 선택 추출, OAuth 대역, 최종 확인, 중복·실패·미확정 상태 처리와 브라우저 흐름을 검사했다.
- 테스트 이미지의 API·워커·로그 필터·SNS 화면·새 회귀 파일 해시를 최종 로컬 소스와 대조해 일치를 확인했다.
- 개발 Compose 구문 검사와 production 이미지 빌드도 통과했다.
- 일반 검사에서 실제 AI·YouTube·운영 DB를 호출하지 않았다. 로컬 결과는 GitHub CI 실행 성공을 뜻하지 않는다.

## 남은 실제 검증

YouTube OAuth 클라이언트 ID·시크릿과 사용자의 계정 연결이 필요하다. 로컬 비밀 파일에 비활성 기본값·Origin·토큰 암호화 키·빈 OAuth 설정 항목만 준비했다. 계정·출력 파일·제목·공개 범위와 아동용 여부를 최종 확인한 뒤 실제 업로드를 별도 수행해야 한다. 로그인·권한 동의는 사용자가 직접 한다. 현재 업로드 성공, 실제 토큰 만료·철회, YouTube 처리 품질을 검증했다고 표시하지 않는다.

실제 Groq 단어 타임스탬프의 정렬 품질과 원음 대비 인식 정확도도 별도 평가 대상이다. 기존 단어 시각 없는 전사는 시각을 추정해 분할하지 않고 검토 필요 상태를 유지한다.
