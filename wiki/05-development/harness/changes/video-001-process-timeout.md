# VIDEO-001 — 시간 초과 후 자식 프로세스가 남는 문제

> 시간 제한으로 부모 프로세스를 멈춰도 자식 도구가 계속 실행될 수 있습니다. 이 실패의 재현 조건, 프로세스 종료 방식의 수정과 검증 한계를 설명합니다.


## 목적과 재현 조건

관련 요구사항은 [VIDEO-001-R07](../requirements-map.md)이다. 영상 작업이 시간 제한을 넘으면 부모와 자식 프로세스가 종료되어야 한다. 사용자 승인 범위는 링크 기반 10초 추출과 그 실패 검증이었다.

Windows 로컬 검사에서 부모 Python이 자식을 실행하도록 했다. 자식은 2초 후 임시 표식 파일을 만들고, 부모는 20초 기다린다. 실행 도구 제한을 0.5초로 두었는데도 표식 파일이 생성되어 자식이 살아 있음을 확인했다. 이 문제는 영상 도구가 중단된 것으로 보이면서 자원을 계속 사용할 수 있다는 의미다.

## 원인과 변경

기존 구현은 `taskkill /T /F` 결과를 확인하지 않은 채 부모 종료를 기다렸다. 관측된 사실은 자식 종료 실패이며, 당시 OS가 taskkill을 실패시킨 구체적인 이유는 확인하지 않았다.

- 제품 코드: [process adapter](../../../../app/adapters/process.py)의 Windows 종료 처리를 psutil로 변경했다. 부모·자식을 일시 중지한 후 자식부터 종료하고 종료 여부를 확인한다. 확인 실패는 별도 오류로 구분한다.
- 하네스: [test_process.py](../../../../tests/process/test_process.py)의 `test_timeout_kills_descendants`를 회귀 검사로 유지한다. 기대 결과를 바꾸거나 검사를 비활성화하지 않았다.

## 검증 근거와 제한

```powershell
uv run python -m pytest tests/process/test_process.py -k timeout -q
uv run python scripts/verify.py
```

수정 후 Windows 로컬에서 관련 검사와 기본 56개 검사가 통과했다. Python 3.12, psutil 7.2.2를 사용했다. 실제 DB·Redis·Celery 검사 2개는 이 근거에 포함하지 않는다. Linux 프로세스 그룹 종료 분기는 이 Windows 실행만으로 검증되었다고 볼 수 없으며 해당 변경의 원격 CI도 아직 확인하지 않았다.

작업 시작 커밋은 `b549c6b6088f087420fec225ed0bc6761082a2cc`이며, 위 검증은 수정 사항을 커밋하기 전에 수행했다. 구현 요청 외의 세부 사람 개입 횟수와 모델 비용은 집계하지 않았다. 이번 파일 구조 정리는 회귀 검사의 위치만 바꿨으며 제품 종료 로직은 변경하지 않았다.
