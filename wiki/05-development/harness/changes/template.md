# 개선 기록 양식

> 상태: 작성 양식 · 기준일: 2026-11-15 · 유지관리: 프로젝트 개발자

[위키 홈](../../../README.md) · [개선 기록 목차](README.md)

새 파일로 복사한 뒤 빈칸을 채우고 작성 상태를 명시한다. 아래 예시 항목 자체를 실제 관측 결과로 사용하지 않는다.

| 항목 | 기록할 내용 |
|---|---|
| 작업·요구사항 ID | Issue 또는 합의한 작업 ID, 관련 요구사항 |
| 목적·완료 기준 | 어떤 실패를 막고 무엇으로 완료를 판단하는가 |
| 시작·종료 버전 | 커밋 또는 미커밋 상태; 값을 추측하지 않음 |
| 요청 근거 | 승인된 요구의 요약·참조; 원본 대화·비밀값 제외 |
| 재현 조건 | 운영체제·입력·도구 버전·실행 명령 |
| 실패와 영향 | 기대 결과와 실제 결과, 사용자·개발에 미치는 영향 |
| 원인 | 확인한 원인과 아직 가설인 부분 구분 |
| 수정 | 제품 코드 변경과 하네스 변경을 구분 |
| 회귀 검사 | 테스트 파일·함수와 재실행 명령 |
| 관측 결과 | 실행한 검사·실패/성공·미실행 검사와 이유 |
| 사람의 결정 | 범위·예산·권한 결정이나 수동 수정; 미기록이면 명시 |
| 모델·비용 | 관측한 값만 기록; 제공되지 않으면 미수집 |
| 남은 제한 | 적용 환경·추가 확인이 필요한 조건 |

비공개 내부 추론은 기록 대상이 아니다. 프롬프트 효과 비교는 같은 작업·시작 코드·완료 기준 등 비교 조건을 명시한 별도 실험으로 다룬다.
