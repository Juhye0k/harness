# 전사 평가·단어 정렬 통합과 실제 샘플 품질 — TR-EVAL-002 / SUB-ALIGN-003

> 상태: 현재 작업 폴더 통합 / 고정 샘플 표시 가독성 미달 · 기준일: 2026-11-16

[위키 홈](../../../README.md) · [개선 기록 목차](README.md)

## 범위와 통합 방식

사용자의 요청으로 두 워크트리의 평가 CLI·정답 입력 화면·단어 정렬 파서·회귀 검사를 현재 작업 폴더에 통합했다. 공통 목차·현황·로드맵은 두 변경을 모두 반영해 병합했다. 기존 미커밋 수정은 먼저 비공개로 보관하고 요청 범위의 파일만 반영했다. 시작 커밋은 `fb9b793`이며 이후 미커밋 변경을 포함한다. 현재 로컬 브랜치는 `feat/integrate-transcript-quality`다. 커밋·원격 푸시·Wiki 게시를 뜻하지 않는다.

[평가 도구 계약](../../transcript-quality-evaluation.md)과 [정렬 복구 계약](../../word-alignment-recovery.md)을 따른다. 기존 원본·전사·실패 이력을 덮어쓰지 않으며 모델·서비스·의존성을 추가하지 않았다.

## 실제 평가의 입력과 기준

기존에 승인된 한국어 대화 영상 1개와 보존한 실제 Groq 응답을 사용했다. 영상 트랙은 404.237초, 1280×720이고 검수 음성은 16kHz·모노 MP3다. 컨테이너 표시 길이 404.261초와 구분해 영상 트랙 길이를 자막 범위 검사의 기준으로 삼았다. 영상·음성·응답·전사 해시와 평가 설정·결과·재현 스크립트는 비공개 평가 폴더에 기록했다. 외부 AI 호출은 0회다.

사용자는 사람이 확인한 정답 전사가 없다고 답했다. 따라서 CER·오인식 탐지 정밀도·재현율과 단어별 원음 경계 정확도는 평가 불가다. 같은 모델의 구간/단어 출력 차이나 높은 신뢰도를 정답으로 대신하지 않는다.

표시 기준은 제품 초안인 줄당 20자·최대 2줄·0.8~6초·초당 15자다. 기존 코드가 붙인 경고만 합산하지 않고, 실제 표시 자막의 시간·문자·줄수에서 다시 계산했다. 구간별 원문 비공백 문자 보존·시각 순서·영상 범위·겹침도 확인했다. 이는 접근성·방송 표준 준수 인증이 아니다.

원문 보존·시각 순서·영상 범위는 통과했다. 문제가 있던 원 구간 3개는 표시 제약을 모두 만족하게 되었고 새로 경고 대상이 된 원 구간은 없었다. 다만 이미 경고 대상인 구간에서 0.5초짜리 짧은 자막이 생겨 최소 시간 위반은 1개 증가했다. 원문·시간을 바꾸지 않고 복구할 수 없는 99개 구간은 유지했다.

**표시 가독성 초안은 미달이다.** 경고 개수 감소만으로 전체 품질 개선이나 제품 합격을 선언하지 않는다. 코드 검사 통과와 실제 결과의 기준 통과를 분리한다.

250ms 경계 허용 실험도 같은 입력으로 비교했다. 단어 사용 구간 70개·표시 자막 133개로 늘었지만, 겹침 8개·짧은 표시 7개가 생기고 전체 위반 자막은 28개로 늘었다. 따라서 기본 파서에는 이 실험을 적용하지 않았다.

## 음성 신호 검사와 한계

저장 MP3에 FFmpeg `silencedetect=noise=-35dB:d=0.3`을 적용했다. 감지된 무음은 48개·총 25.330초이고, 표시 시간의 80% 이상이 이 무음 구간과 겹치는 자막은 0개였다. 임계값과 80% 기준은 이번 진단 설정이며 검증된 음성 인식 기준이 아니다. 에너지 신호만으로 실제 발화 여부·정확한 단어 경계·오인식 여부를 확정하지 않는다.

미확정 정답을 채우거나 기존 전사를 사람의 검수 완료로 바꾸지 않았다. 정답 입력 팩·SRT·비교 화면·평가용 영상은 비공개 위치에서 검토한다. 이 평가는 한 영상에 한정되며 다른 장르의 품질을 보장하지 않는다.

## 검증과 후속 작업

통합한 코드의 `scripts/verify.py`는 기본 **282개**·Ruff·서식·Alembic 오프라인 SQL이 통과했다. 격리 PostgreSQL·Redis·Celery·FFmpeg·Chromium 통합 **61개**도 통과했다. 통합 검사 이미지는 의존성을 재사용하고 합친 소스를 읽기 전용으로 연결한 뒤 소스·테스트·스크립트·`uv.lock` 해시를 확인했다. 검사는 외부 AI·실계정 SNS에 접속하지 않으며 전용 컨테이너·네트워크·테스트 볼륨은 정리했다. 기존 Starlette/httpx 사용 중단 예정 경고 1개는 남아 있다.

일반 개발 Compose의 이미지 빌드와 API·영상/분석 워커 기동도 성공했다. 저장 응답을 수정 파서로 처리한 결과는 원본 분석을 덮어쓰지 않고 새 분석·전사로만 추가했다. 출처 분석·응답 해시·정렬 버전과 `offline_word_alignment_replay`, `external_call=false`를 기록했고, 기존 실패 이력·전사·기존 호출 기록은 보존했다. 이는 운영자의 일회성 재처리이며 자동 재시도·캐시 마이그레이션 기능이 아니다.

개발 서버의 실제 결과는 원 전사 121개·단어 사용 22개·표시 자막 125개·검수 대기 23개다. HTTP 자막·SRT 일치·음성 Range 206과 Chrome의 실제 음성 재생·필터·새로고침 무변경을 확인했다. 평가용 10초 MP4는 10.010초·영상/음성 트랙을 확인했고 실제 재생도 검사했다. 비교 보고서는 모바일 가로 넘침 없이 열렸다. 대표 프레임을 직접 확인했으며 긴 9줄 자막이 인물을 가리는 문제를 품질 미달 근거로 남겼다. 정답 입력에는 사람의 원음 확인 판정을 대신 넣지 않았다.

다음은 최소 표시 시간 분할 회귀, 남은 긴 구간의 신뢰할 수 있는 단어 정렬, 원음 확인 정답 표본 확보다. 실제 품질 미달을 숨기기 위해 제한을 늘리거나 원문을 삭제·임의 수정하지 않는다. 수치 합격 기준이나 사람 검수 결과를 만들어 넣지 않는다.
