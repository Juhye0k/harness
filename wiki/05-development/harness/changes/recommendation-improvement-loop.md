# 선택 피드백과 종료 조건 기반 개선 루프 — RECO-EVAL-001

[위키 홈](../../../README.md) · [개선 기록 목차](README.md)

## 목적과 완료 기준

실제 수작업 평가·수정·재검증 1~3회를 기록하고 이후 반복 절차를 자동화할 도구를 구현한다.
선택과 품질 판정 분리, 입력 고정·회차 비교, 주요 문제와 사람 확인·연속 2회 검사 기반 종료가 기준이다.
기존 사용자 변경을 보존했으며 기록 시 HEAD는 `0167efd`, 이 작업은 미커밋 상태다.
별도 AI·서비스·의존성을 추가하지 않았다. 실제 사람 평가와 AI 작업자 연결은 미수행이다.

## 변경과 검증 근거

평가 CLI를 확장하고 순수 비교·종료 정책과 명시적 argv 기반 실행기를 추가했다.
실제 하위 프로세스 회귀에서 4회 수정 후 동일 코드의 연속 2회 검사로 종료함을 확인했다.
시간 초과·입력 불일치·보호 테스트 변경·동시 실행·손상된 이력·사람 확인 대기를 검사한다.
최종 `uv run python scripts/verify.py`는 기본 331개·Ruff·서식·Alembic 오프라인 SQL 통과다.
실제 PostgreSQL·Redis·Celery·FFmpeg·Chromium 통합은 64개 통과했다.
평가 CLI의 조회·집계·비교로 provider_calls가 증가하지 않는 것도 실제 API와 DB에서 확인했다.
기존 이미지와 현재 uv.lock 해시 일치를 확인하고 현재 소스를 읽기 전용으로 연결한 전용 프로젝트에서 검사했다.
전용 컨테이너·네트워크·테스트 볼륨은 정리했다. 개발 환경과 실제 계정은 변경하지 않았다.

초기 실행은 uv 캐시·공용 pytest 임시 폴더 권한으로 차단되어 승인된 실행과 전용 임시 폴더를 사용했다.
테스트 파일명 충돌과 Windows 기본 인코딩으로 UTF-8 보고서를 읽는 실패를 수정했다.
검사 실패가 있으면 사람 검토 대기보다 자동 수정 가능한 실패를 먼저 해결하도록 종료 정책을 보완했다.
기존 Starlette/httpx 사용 중단 예정 경고는 남아 있다. 비용·토큰 측정값은 미제공이다.

## 남은 작업

승인된 실제 입력의 사람 평가 1~3회로 평가 기준과 원인을 확인한다.
현재 worker는 로컬 코딩 작업자를 연결하는 인터페이스이며 실 AI를 자동 연결하지 않는다.
외부 호출 예산 강제·실제 사용자 인증·게시 기능을 구현한 것으로 설명하지 않는다.
상세 명령과 계약은 [추천 개선 루프](../../recommendation-improvement-loop.md)를 따른다.
