# 원본 화면 자막을 이용한 자동 평가 — CAPTION-OCR-001

> 원본 화면 자막을 기준으로 비교 루프를 실행하고, YouTube 자동 자막의 단어 시각으로 29개 자막 초안을 만들었다. 같은 기준 구간에서 문자 차이율이 기존 15.4%에서 6.3%로 낮아졌고 표시 형식을 통과해 새 미확정 편집본으로 저장했다. OCR로 만든 더 나쁜 초안은 자동 채택하지 않았다.

## 요청과 완료 기준

사용자 요청 요약: 시간과 내용을 사람이 제어하기 어려우므로 원본 영상에 이미 있는 자막을 기준으로 테스트 루프를 실행한다. 시작 커밋은 `d46bc4e`이며 기존 작업 폴더의 다른 변경은 보존하고 별도 브랜치에서 진행한다.

첫 범위는 기존 실제 후보 한 개다. 원본 해시와 편집 버전을 고정하고, 화면 하단의 자막만 추출한 다음 현재 저장본과 문구·시간·누락·형식을 비교한다. 비교에 쓰지 않은 프레임도 확인해 기준을 그대로 복사한 결과를 품질 개선이라고 평가하지 않는다. 일반 CI는 합성 관측값만 사용한다.

원본 자막도 편집 오류가 있을 수 있다. OCR 결과는 원음 정답이나 사람 검수 결과로 표시하지 않는다. 새 외부 AI 호출·계정 게시 없이 로컬 도구로 수행하며 원본 영상·자막·추출 프레임은 공개하지 않는다.

## 실행 과정과 결과

원본은 기존 404.237초 영상이며 첫 후보 59.36~91.68초를 사용했다. 100ms 간격의 자막 영역 334프레임을 추출했고 원본 해시가 기존 값과 같음을 확인했다. 원본 화면을 AI가 읽은 18개 표시 구간을 프레임 해시와 묶어 고정했다. 이 기준선은 사람이 원음을 확인한 정답이 아니며, 새 영상에 대한 모델 성능 평가도 아니다.

기준 구간은 27.8초·208글자이며 후보 시간의 약 86.0%다. 72.3~76.6초에는 실제 원본 화면에 하단 자막이 없고 기사 본문만 있어 해당 시간은 평가하지 않았다. 남은 가장자리도 기준 범위에 포함하지 않았다.

| 동일 기준선에 비교한 결과 | 화면 자막 대비 문자 차이율 | 채택 판단 |
|---|---:|---|
| 기존 저장 편집본 26개 | 15.4% | 기준선 |
| Windows OCR, 첫 전처리 | 64.4% | 내용·표시 규칙 미달 |
| Windows OCR, 영역·흑백 반전 개선 | 35.1% | 내용·표시 규칙 미달 |
| Tesseract 한국어 OCR | 29.3% | 내용·표시 규칙 미달 |
| YouTube 한국어 자동 자막의 단어 시각으로 만든 29개 | 6.3% | 미확정 초안으로만 저장 |

원본 화면에는 기존 전사와 다른 표현이 있었다. YouTube 자동 자막은 그중 일부를 더 잘 보존했고, 화면 자막이 없는 구간의 초안도 제공했다. 그 시간의 정확도는 측정하지 않았다. YouTube에 제작자 자막 파일은 없었으며 받은 파일은 자동 자막이다. 실제 자막 문구는 공개 문서에 복사하지 않는다.

새 초안은 `0d81490e-32e7-4695-8cfb-4430803e9078`이다. 원본 전사와 이전 26개 편집본은 보존했고 저장 직전 최신 편집이 바뀌지 않았는지 조회했다. 29개 모두 원 구간 8개에 연결되고 기존 표시 규칙을 통과했다. 같은 시각의 두 단어는 합쳐 보존하며, 읽기 속도를 맞추려고 단어를 삭제하지 않는다.

후보의 양 끝에 걸친 단어 2개를 별도로 검출했다. 완전한 단어 표시 구간 기준의 범위 제안은 59.60~91.60초지만 실제 후보 범위는 변경하지 않았다. 표시 끝은 다음 단어 시작에서 얻은 값으로 실제 음성 종료를 검증한 것은 아니다. 원음 확인 항목·최종 출력·SNS 게시 상태도 바꾸지 않았다.

### 후속 조회에서 발견한 완성 파일 검사

평가 초안 저장 후 다시 조회하니 같은 29개 문구의 별도 버전 `2001ad63`이 확인 상태로 저장되고 출력 작업도 완료돼 있었다. 이 평가 작업이 확인 항목을 변경하거나 출력을 접수한 것은 아니며, 누가 원음을 확인했는지는 검증하지 않았다. 이미 만들어진 파일을 읽기만 하여 검사했다.

MP4는 720×1280·32.3323초이며 영상·음성 트랙과 전체 디코딩을 통과했다. 내려받은 SRT는 해당 버전에서 클립 기준으로 변환한 29개 문구·시간·줄바꿈과 정확히 일치했고 원본 해시도 보존됐다. 이는 파일·버전 일치 검사이며 실제 발화 정확도·최종 시청 품질·SNS 게시 통과를 대신하지 않는다.

출력의 2·8·27초 프레임도 확인했다. 한국어 새 자막이 표시되지만 원본에 새겨진 자막과 동시에 보이고 위아래 검은 여백이 크다. 따라서 미디어 계약 통과와 완성본의 화면 품질을 구분하며, 원본 자막 처리·세로 화면 구성은 후속 개선으로 남긴다. 기준 프레임 해시가 비어 있거나 자막을 모두 없앤 초안도 통과하지 않도록 검사했다.

## 실패와 수정

첫 OCR에서는 글자 아래가 잘려서 영역 판별을 수정하고 흰 배경·검은 글자와 여백을 사용했다. OCR 엔진을 바꾸어도 기존 전사보다 차이율이 커서 그대로 교체하지 않았다. Tesseract TSV의 글자 자체에 따옴표가 들어가면 CSV 해석이 후속 행을 삼키는 오류가 있어 TSV 따옴표 해석을 끄고 회귀 검사를 추가했다.

YouTube 자막의 화면 표시 길이를 단어 길이로 쓰면 구간이 중첩된다. 따라서 단어 시작 시각을 사용하고 다음 시작까지를 표시 구간으로 제안했다. 줄바꿈 이벤트와 같은 시각에 나온 여러 단어를 구분하는 검사도 추가했다.

첫 전체 기본 검사는 Windows 공용 pytest 임시 폴더의 접근 거부로 262개 통과·134개 준비 오류가 났다. 기존 임시 폴더 권한을 바꾸지 않고 이 워크트리 안에 전용 임시 경로를 정해 재검사했다. 이후 Ruff·서식·기본 396개·Alembic 오프라인 SQL이 통과했다. Starlette/httpx 사용 중단 예정 경고 1개는 남는다. 통합 107개는 기본 검사에서 제외됐으며 이 작업에서 통과했다고 대신 보고하지 않는다.

## 산출물과 범위

구현·명령·판단 규칙은 [원본 자막 평가 실행 안내](../../source-caption-evaluation.md)에 정리했다. 원본 프레임·실제 자막·서명된 다운로드 URL·전체 로그는 비공개 실험 폴더에만 보관하고 공개하지 않는다. 일반 CI는 합성 기준선·단어 시각·잘못된 해시·누락·따옴표·교차 평가·자동 승인 방지를 검사한다.

새 유료 모델 API 호출은 없었다. YouTube 공개 메타데이터와 자동 자막 파일은 내려받았으며 OCR 처리는 로컬에서 수행했다. 개발 에이전트의 시각 판독 비용·사용량은 도구에서 제공하지 않아 알 수 없음이다.

이번 작업으로 모든 자막의 문구·시각을 사람이 처음부터 입력할 필요는 줄었지만, 사람의 원음 검수 완료나 제품 API의 원본 자막 자동 수집을 구현한 것은 아니다. 현재 단계는 평가 CLI·반복 실행 근거·새 미확정 편집본이다. 로컬 작성과 Wiki 게시는 별도로 확인한다.
