# 화면 관측과 단어 시작 시각을 이용한 표시 정렬 — CAPTION-ALIGN-002

> 원본 화면 자막이 바뀌는 곳에서 가까운 단어 시작을 찾아 자막을 나눴다. 고정 영상에서 전체 문구와 구간별 차이가 각각 7/208(3.37%)인 34개 초안이 표시 규칙을 모두 통과했다. 원음 확인과 새 영상에서의 검증은 남아 있다.

[작업 기록 목차](README.md) · [이전 평가 기록](2026-11-18-source-caption-loop.md)

## 요청과 완료 기준

사용자 요청 요약. 별도 작업 트리에서 같은 원본과 평가 범위를 유지하며 구현과 검증을 반복한다. 전체 문구 차이율은 기존 29개 초안의 13/208 이하, 구간별 차이율은 원래 26개 편집본의 72/208 미만이어야 한다. 모든 표시 규칙을 통과하고 원음 확인은 사람이 결정한다.

시작 커밋은 `30aec9034bfe976dc1819d2207775193ae56fa0b`다. 분리 작업 트리는 시작할 때 깨끗했고, 루트에는 다른 작업의 미커밋 변경이 있었다. 기존 영상과 자막 관측으로 재현하며 유료 호출과 SNS 게시 없이 진행한다.

## 구현·실험과 결과

길이와 줄 수로만 분할하던 29개 초안은 화면 자막이 바뀌는 경계를 넘는 경우가 있었다. 예를 들어 앞 화면의 끝 단어와 다음 화면의 첫 단어를 한 자막으로 표시하면, 중심 시각으로 배정하는 구간 검사에서 앞 화면의 단어가 빠지고 다음 화면에 같은 단어가 추가된다.

1. 변경 전에는 저장된 29개 초안의 13/208·82/208을 재현했다.
2. OCR에서 감지한 전환 시각을 그대로 분할 비용에 쓰면 샘플링 지연으로 단어 시작을 조금 지나치는 경우가 생겼다. Windows OCR 실험에서 구간별 차이는 53/208로 줄었지만 전체 문구는 15/208로 목표에 미달했다.
3. 짝수 프레임에서 연속 네 관측의 정규화한 문자 차이를 비교했다. 같은 쪽의 변화가 각각 40% 이하이고 가운데 차이가 55% 이상일 때 전환으로 등록했다. 관측 한 칸(이 실험에서는 100ms) 이내의 가장 가까운 단어 시작에 연결하고, 분할 후보가 이 경계를 넘을 때 비용 2를 더했다. 읽기 규칙상 필요하면 경계를 넘을 수 있다.
4. 위 설정을 Windows OCR과 Tesseract 기존 관측에 각각 적용했다. 원본 자막 문구와 시각을 정답 파일에서 가져오지 않았으며 초안에는 자동 자막 어절과 시작 시각만 사용했다. 각 끝은 다음 단어 시작을 쓴 표시 시각이다.

| 같은 화면 기준선의 비교 | 전체 문구 차이 | 구간별 차이 |
|---|---:|---:|
| 고정 편집본 26개 | 32/208 (15.38%) | 72/208 (34.62%) |
| 이전 29개 초안 | 13/208 (6.25%) | 82/208 (39.42%) |
| Windows OCR 정렬 34개 | 7/208 (3.37%) | 7/208 (3.37%) |
| Tesseract 정렬 32개 | 7/208 (3.37%) | 24/208 (11.54%) |

두 새 초안 모두 완전히 들어오는 82어절의 문구와 순서를 보존했다. Windows OCR 초안 34개는 모두 한 줄이고 각 0.50~1.70초이며 최대 15자/초다. 후보 범위·정렬·겹침·원본 구간 연결을 포함한 제품 편집 검증도 통과했다. 59.36~91.68초 후보의 범위는 그대로이며 표시 자막은 59.60~91.60초 안에 있다. 후보 양끝과 교차하는 두 단어는 미해결로 기록했다. 원음 확인 상태가 false인 로컬 초안 JSON을 만들었고, 조회 대상 로컬 서비스가 응답하지 않아 서비스에 새 버전을 저장하지 않았다.

짝수 프레임은 경계 감지에, 홀수 프레임은 별도의 OCR 문구 일치 확인에 썼다. Windows OCR에서 기존 0/139 프레임이 정확히 일치했고 새 초안은 11/139였다. 이 검사는 원본의 긴 자막 한 덩어리와 새 짧은 자막 한 덩어리의 문구가 완전히 같은지를 보기 때문에, 고정 기준선의 구간별 비교와 값이 다르다. 최종 점수에는 기존에 고정한 화면 판독 18구간·27.8초·208글자와 동일한 비교 함수를 사용했다. 화면 자막이 없는 72.3~76.6초는 미평가다. 같은 영상에서 설정을 실험했으므로 이 결과로 발화 종료나 새 영상의 정확도를 판단할 수 없다.

## 세로 출력의 중복 자막과 여백

이전에 만들어진 MP4의 2·8·27초 프레임에서 원본 화면 자막과 새 자막이 함께 보였다. 720×1280 중 404픽셀이 원본 화면 높이여서 위아래 검은 영역이 약 68%를 차지했다. 가로 중심을 잘라 채우는 방식은 기사와 화면 우측 화자를 잃을 수 있어, 원본 전체를 보존하고 배경색과 원본 바로 아래의 자막 위치를 바꾸는 방식을 합성 영상으로 시험했다.

합성 영상에서 원본 자막이 있는 시각을 미리 지정하고 그때 새 자막을 숨겼다. 그 밖의 시각에는 새 자막을 원본 바로 아래에 표시했다. 양쪽 끝 픽셀 보존, 음성 트랙·길이·전체 디코딩·원본 해시 검사를 통과했다. 여백의 색과 자막 위치를 바꿨고 원본 화면이 차지하는 면적은 가로 구도에 제약받는다. 실제 영상 전체의 자막 유무와 가독성을 확인하기 전에는 이 생략 방식을 제품 렌더러에 연결하지 않는다.

## 검증과 기록

- 개발용 CLI를 `--align-to-ocr` 옵션으로 두 개의 기존 OCR 관측에 실행했다. 원본과 프레임 파일 334개의 해시를 다시 계산했고 기준선·고정 편집본·기존 초안·OCR·단어 시각·취득 기록의 해시와 비교 결과를 비공개 실험 폴더에 기록했다.
- `uv run python scripts/verify.py`에서 Ruff 검사·서식·기본 403개·Alembic 오프라인 SQL이 통과했다. 기존 Starlette/httpx 경고 1개가 남았다. 통합 107개는 로컬 기본 검사에서 제외되며 원격에서는 해당 커밋의 필수 CI로 확인한다. 세 회귀 검사는 홀수 프레임 무시와 일회성 오인식 배제, 인접 단어 시각에서의 무손실 분할, 짧은 단어의 읽기 규칙을 확인한다.
- Windows의 공용 uv 캐시에 쓰기 권한이 없어 작업 트리 전용 캐시로 바꿨다. 기존 uv 환경을 재사용했고, FFmpeg는 기존 로컬 도구로 실행했다. 새 모델 호출과 SNS 게시는 없었다. 개발 에이전트의 모델 사용량·비용은 도구에서 제공되지 않았다.
- 사용자는 품질 목표·같은 입력 사용·원음 확인 보류를 정했다. 경계를 선호하는 분할과 합성 레이아웃 실험은 에이전트가 구현·검증했다. 원음 확인은 사람이 판단할 항목으로 남겼다.

## 포트폴리오에 옮길 근거

전체 문구 점수만 보면 기존 초안의 시간 손실을 놓친다. 화면 전환과 단어 시작을 연결한 뒤 전체 문구와 구간별 차이를 같은 자료로 대조하여, 고정 사례에서 29개 초안의 13/208·82/208을 34개 초안의 7/208·7/208로 개선했다. 이 기준과 전체 어절 보존 검사를 갖추면 사람이 검토할 자막 초안을 다시 만들 수 있다.
