# 영상이 끝까지 재생돼도 자막이 두 번 보였던 이유

> 검수한 편집본을 내려받아 보니, 원본 영상에 이미 새겨진 대사 아래에 편집 자막이 다시 보였습니다. 영상에 그리는 자막과 내려받을 자막 파일의 조건을 따로 검사했습니다.

원본의 글자는 영상 픽셀에 들어 있습니다. 편집 자막을 세로 화면 아래 띠에 그리면 두 문장이 동시에 보입니다. 원본 화면 전체를 보존하고, 편집자가 원본 자막을 확인한 시간에만 아래 띠의 글자를 숨기기로 했습니다. 내려받은 SRT는 검수한 대사 전체를 담아야 하므로 같은 숨김 조건을 적용하면 문장이 누락됩니다.

## 어떻게 대조했나

11월 19일 출력에서 자막이 겹쳤던 클립을 main `b09265e`로 다시 출력했다. 사용자가 원음과 시간을 확인한 편집 버전과 원본을 격리 환경에 복원하고, 기존 원본 화면 관측 18개의 프레임 해시를 대조해 연속된 두 구간을 지정했다. 구간 시각은 클립 시작 기준이다.

| 클립 구간 | 실제 출력에서 확인한 결과 |
|---|---|
| 0.140~12.940초, 17.240~32.240초 | 0.540초와 31.790초 표본에서 원본 화면 자막이 보였고 그 아래의 편집 자막은 사라졌다. |
| 12.940~17.240초 | 15.940초 표본에서 편집 자막이 다시 보였다. |

이전·새 MP4의 969프레임을 같은 표시 시각에 맞춰 아래 자막 띠를 비교했다. 지정 구간 안에서만 편집 자막을 숨기는 규칙과 어긋난 프레임은 0개였다. 같은 출력 작업에서 받은 SRT의 번호·문구·줄바꿈·클립 기준 시각을 검수본과 34개 모두 대조했고, SRT 파일도 이전 출력과 바이트 단위로 같았다.

세로 MP4는 720×1280, 32.3323초였다. 영상과 음성을 끝까지 디코딩했고 Chrome에서 1배속 재생이 끝까지 진행됐다. 브라우저에서 받은 MP4와 SRT는 각각 API에서 직접 받은 파일과 일치했다. 브라우저 재생 통계에는 표시 누락 4프레임이 기록됐다.

검증 범위는 실제 클립 한 건이다. 원본 자막 경계는 100ms 간격으로 화면을 관측해 정했으며 약 ±200ms의 불확실성이 있다. 기본 검사 425개가 통과했다. 이 출력의 SNS 게시는 별도 단계다.

### 같은 클립으로 재검사하는 방법

Windows에서 승인된 원본·편집 버전과 구간 지정 전후의 MP4, 같은 작업에서 받은 SRT를 준비한다. 다음 명령의 파일명은 로컬 복사본을 가리킨다.

```powershell
ffprobe -v error -select_streams v:0 -show_entries frame=best_effort_timestamp_time -of csv=p=0 after.mp4
ffmpeg -v error -xerror -i after.mp4 -map 0:v:0 -map 0:a:0 -f null -
uv run python scripts/verify.py
```

1. 두 MP4에서 프레임 표시 시각 목록이 같은지 확인한다. 각 파일에 FFmpeg 필터 `crop=720:120:0:754,format=gray`를 적용해 자막 띠를 잘라낸다. 각 프레임에서 밝기 180을 넘는 픽셀이 100개를 초과하면 편집 자막이 보이는 것으로 센다. 이 좌표와 기준은 이 클립의 출력 프로필에 맞춘 값이다.
2. 지정 구간 안의 새 자막 띠는 비어 있어야 한다. 그 밖에서는 이전 출력과 표시 여부가 같아야 한다. 경계에서도 같은 규칙을 적용하고, 두 구간 안쪽과 사이에서 원본 화면과 띠를 직접 비교한다.
3. UTF-8 SRT 블록을 번호순으로 읽어 검수본의 줄별 문구와 비교한다. 각 자막의 시작·종료 시각에서 클립 시작 시각을 뺀 값이 SRT 시각과 밀리초 단위로 일치하는지 확인한다.


## 운영체제가 달라도 같은 실수를 잡는 검사

처음 Linux 검사에서는 글자의 왼쪽 시작점이 160보다 작아야 했는데 실제 값은 174였습니다. 같은 문장을 다른 폰트로 그리면 글자 폭은 달라져도 가운데 정렬은 맞았습니다. 이후에는 각 줄의 중앙과 좌우 여백을 재고, 큰 캔버스에 그린 기준 글자와 실제 픽셀을 비교해 잘림을 검사했습니다. Linux에서 글자를 24픽셀 옮기거나 끝을 지웠을 때 검사가 실패했습니다. [재현 환경·픽셀 기준](2026-11-18-flow-output-layout.md)

표시용 자막의 분할은 더 앞 단계입니다. 21초·173자 전사 구간의 합성 사례에서는 검증된 단어 시각으로만 자르고, 시간이 없는 구간은 검토 대상으로 두었습니다. 프레임 일치만으로 원음과 대사가 맞는지 알 수 없어 최종 출력 전에 사람이 듣고 확인합니다. [표시 분할의 재현 기록](../changes/video-005-subtitles.md)
