# Wiki 가독성과 탐색 구조 개편

> 카테고리와 개별 글이 뒤섞이고 과거 게시 이력이 본문보다 먼저 보여 원하는 내용을 찾기 어려웠습니다. 전체 문서의 도입부·설명 순서·현재 상태를 검토하고, 주제별로 펼치는 사이드바와 글 바로가기를 구성한 작업입니다.

## 요청과 완료 기준

사용자는 전체 Wiki를 처음 읽는 사람도 이해할 수 있게 다듬고 인용 블록으로 주제를 먼저 설명하도록 요청했습니다. 사이드바는 카테고리를 펼친 뒤 글 제목을 누르면 직접 이동하는 방식을 선택했습니다. 후속 요청 “Implement the plan.”에 따라 원본 변경·검증·main 반영과 별도 Wiki 게시까지 진행합니다.

시작 코드는 main `0f84dc0`입니다. 기존 작업 폴더의 미커밋 변경은 보존하고 별도 작업 폴더에서 진행했습니다. 기존 84개 문서를 검토하고 이 작업 기록을 추가했습니다. 개발 에이전트의 정확한 모델·사용량·비용은 알 수 없음입니다.

## 변경과 판단

모든 글의 주제를 문장으로 요약하고 긴 설명을 문단으로 나눴습니다. 실행·API 문서의 명령과 입력·오류 계약은 유지했습니다. 현재 실행 흐름은 업로드·전사·편집·SNS 순서로 다시 썼으며, 미구현으로 남아 있던 설명을 코드와 대조했습니다. 작업 기록은 결과를 먼저 읽고 당시 프롬프트·실패 과정을 따라가도록 순서를 조정했습니다.

주 카테고리는 9개로 나누되 기존 문서 주소는 유지합니다. 분류 목록과 게시본 생성기를 원본에 포함해 새 글이 빠지거나 사이드바에 수동으로 누적되는 문제를 검사합니다. 과거 검사 수치·원문 발췌·실패·미검증 한계는 보존합니다. 참고한 글 구성은 [작성 규칙](../../../07-governance/document-guide.md)에 연결했습니다.

## 검사와 게시

기본 375개·Ruff·서식·Alembic SQL이 통과했습니다. 최종 문서 86개·카테고리 9개·상대 링크 630개·다이어그램 8개를 확인했고 분류 누락·중복 주소·기존 명령/JSON 코드 블록 변경은 없었습니다. 게시본 생성기의 최초 검사에서 기존 workflow 별칭 주소 충돌을 발견해 실제 Wiki의 legacy 주소를 유지하도록 수정했습니다. 실제 GitHub 화면 확인은 게시 후 수행합니다. 제품 기능·유료 AI·SNS 전송·운영 배포는 변경하지 않습니다. 원격 반영과 최종 CI는 이 문서가 포함된 PR에서 확인할 수 있습니다.

## 시각 자료 추가 요청

사용자는 후속으로 동작 과정이나 구조를 이해하는 데 도움이 되는 곳에 그림·아키텍처·시퀀스 다이어그램을 요청했습니다. 시스템 구성·업로드·작업 상태·편집 흐름·로그인·개발 절차·SNS 실패·Wiki 게시에 Mermaid 8개와 해설을 추가했습니다. 반복 공통 푸터의 옛 게시 상태는 별도 이력 페이지로 보존했습니다.
