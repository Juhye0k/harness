# 위키를 처음 읽는 개발자도 따라갈 수 있도록 정리

> 처음 합류한 개발자가 영상 한 편의 처리 과정을 따라가면서 README, 시스템 그림, Wiki를 함께 읽을 수 있도록 문서의 입구를 정리한다. 아래에는 독자가 헷갈렸던 지점과 개편 기준을 남겼다.



현재 상태와 과거 작업 이력을 분리하고, 주요 문서를 **핵심 요약 → 배경 → 진행 과정 → 확인 결과 → 다음 행동** 순서로 다듬었다. 홈에서 전체 흐름을 파악한 뒤 필요한 기능 문서와 상세 근거를 찾아갈 수 있다. 제품 코드와 검사 조건은 변경하지 않았다.

## 실제 편집본으로 설명하는 백엔드

후속 요청은 현재 구현을 처음 보는 백엔드 개발자를 위해 README와 Wiki를 다시 쓰고 시스템 그림을 갱신하는 일이었다. 기준 버전은 실제 추천·게시 결과가 병합된 `c50c1f4`다. 기술 이름을 나열하는 대신 한 편의 영상을 접수해 출력하고 게시하는 순서에 맞춰 설명한다. [실행 흐름](../../../03-architecture/runtime-flows.md)

문제와 개선 결과를 한 사례에서 비교한다. 원본 화면에 자막이 있던 구간은 새 자막과 겹쳤다. 보정 후에는 그 구간에서만 편집 자막을 숨기고 SRT에는 검수한 자막을 모두 보존한다. 추천 후보 수와 게시 제목처럼 검증이 미달한 항목은 후속 작업으로 표시한다. 문서의 완료 기준은 독자가 첫 화면에서 실행 방법과 이 검증 근거를 찾고, 그림에서 작업 ID와 영상 파일이 각각 어디로 가는지 구분할 수 있는 것이다.

## 요청과 완료 기준

사용자 요청 원문 발췌:

> 지금 너가 남겨주는 위키가 사람이 읽기 힘들어. 가독성 좋게 개선해줘. 글 초두에 두괄식으로 뭐할지 요약해주고 그 과정을 이해하기 쉽게

후속 요청 요약: 변경 통합·실행 환경 반영·실제 영상 검증을 각각 워크트리에서 진행하고 PR·main·Wiki까지 반영한다. 해당 검증 결과는 각 작업 기록에 연결한다.

완료 기준은 핵심 문서의 첫 문단에서 목적·현재 결론을 이해할 수 있고, 신입 개발자가 전체 흐름과 다음 행동을 순서대로 따라갈 수 있는 것이다. 과거 실패와 검사 근거는 삭제하지 않고 별도 이력으로 보존한다. 링크·구현 상태·게시된 화면을 확인한다.

## 시작 상태

- 시작 코드: PR #8의 `1818e5c`. root의 미커밋 변경과 기존 워크트리는 유지한다.
- 문서 작업 브랜치: `docs/wiki-readability-20261118`.
- 원격 Wiki를 새로 받아 직접 수정된 내용·게시 이력을 확인했다.
- 문제: 첫 화면의 긴 검사 이력, 현재/과거 상태 혼합, 구현한 기능의 미구현 표기, 과정 설명보다 파일·약어 나열이 먼저 등장했다.

## 진행과 검증

1. 홈을 제품 목표·현재 범위·읽는 순서·목적별 문서 찾기로 정리했다.
2. 현황은 최신 기능·남은 작업만 남기고 이전 기록 전체를 별도 검증 이력으로 보존했다.
3. 개발 계획·시스템 구조·실행 흐름을 현재 구현에 맞췄다. 이미 있는 자막 편집·출력을 미구현으로 표시하던 부분을 바로잡았다.
4. 사용자 흐름을 단계별 행동·내부 처리·다음 조건으로 설명하고, 주요 기능·하네스 문서의 첫 문단에 요약을 추가했다.
5. 작성 규칙과 작업 기록 양식에 요약·과정·확인 결과·다음 행동의 순서를 반영했다.

저장소 위키 전체의 상대 링크 **634개**가 존재함을 확인했고 diff 공백 검사도 통과했다. `uv run python scripts/verify.py`에서 Ruff·서식·기본 **375개**·Alembic 오프라인 SQL이 통과했다. 통합 107개는 기본 검사에서 제외했다. 제품 코드가 같아 해당 main의 [통합 CI](https://github.com/Juhye0k/short-form/actions/runs/44110488002) 근거를 재사용하며, 문서 PR의 CI도 따로 확인한다.

첫 로컬 검사는 새 워크트리에서 FFmpeg 경로를 찾지 못해 7개 실패·9개 setup 오류가 났다. 기존 설치 경로를 해당 프로세스의 PATH에 연결한 뒤 같은 검사를 통과했다. 제품 코드·테스트 assertion·시스템 전역 설정을 바꾸지 않았다. 기존 Starlette/httpx 사용 중단 예정 경고 1건은 남는다.

제품의 추천·자막 품질이나 가독성 개선률을 측정한 작업은 아니다. 가독성에 대한 사용자 직접 검수는 별도다. 원격 게시 확인은 아래 게시 정보와 연결 PR에서 구분한다.

## 사람·AI 역할과 게시

사용자는 결론부터 설명하고 과정을 쉽게 풀도록 방향을 정했다. AI는 읽는 순서·문서 분리·상태 대조·게시를 담당한다. 정확한 모델·개발 사용량·비용·시간은 알 수 없음이다. 사용자 직접 가독성 검수는 대기 중이다.

GitHub Wiki에 개선 문서 34개와 사이드바를 게시했다. 게시 후 홈·현재 현황·실행 흐름 페이지를 실제로 열어 요약과 본문 반영을 확인했다. 위키 내부 링크도 대상 페이지가 있는지 검사했다.

[개선된 홈](https://github.com/Juhye0k/short-form/wiki) · [현재 현황](../../../07-governance/status.md) · [실행 과정](../../../03-architecture/runtime-flows.md)

게시 후 일부 작업 기록에서 PowerShell의 기본 표준입력 인코딩으로 한글이 물음표로 바뀐 것을 발견했다. UTF-8 파일을 직접 실행하는 방식으로 복구하고 전체 Markdown의 연속 물음표·대체문자와 게시 본문을 다시 확인했다. 제품 코드에는 영향이 없다.

코드 저장소의 문서 원본도 별도 PR로 반영한다. 실제 자막 검토와 최종 출력의 남은 조건은 [실제 영상 작업 기록](2026-11-18-real-video-flow.md)과 구분한다.
