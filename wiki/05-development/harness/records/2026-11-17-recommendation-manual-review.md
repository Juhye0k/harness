# 추천 수작업 평가 웹 연결 — RECO-EVAL-001

> 상태: 일부 완료 — 실제 후보·평가 페이지 준비, 사람 검수 대기 · 기준일: 2026-11-17

[위키 홈](../../../README.md) · [작업 기록 목차](README.md)

## 요청과 완료 기준

사용자 요청 요약: 검증하고 수작업 평가 웹 페이지를 열며, 평가 후 자동화에 연결한다.
사용자는 기존 승인 샘플의 Groq 무료 추천 1회(후보 생성·채점 각 최대 1회)를 승인했다.
유료 전환·자동 재시도 없이 저장된 성공 전사를 재사용한다.
완료 기준은 실제 후보·영상이 표시되는 페이지와 평가 저장·자동화 인계 데이터 생성, 브라우저 검증이다.

## 시작 상태와 제약

기존 미커밋 변경이 있으며 다른 작업 변경은 보존한다. 실제 DB에는 추천 후보 없이 전사 결과만 있었다.
평가 CLI·반복 실행기는 존재하지만 웹 수작업 평가 화면은 없었다.
사용자의 사람 평가 판정을 대신 입력하지 않는다. 개발 에이전트 사용량·비용은 알 수 없음이다.
기존 [반복 루프 구현 기록](../changes/recommendation-improvement-loop.md)과 연결한다.

## 결과와 검증

웹 평가 저장·복원·저장 충돌·외부 Origin 차단·자동화 인계와 세션 준비의 단위 검사 3개가 통과했다.
로컬 평가 서버는 기동했으나 브라우저 자동 제어가 현재 URL을 신뢰성 있게 확인하지 못해 중단됐다.
실제 추천 후보가 없어 수작업 추천 품질 평가는 미완료다. Wiki 미게시.

## P2 — 인증 오류 해결 요청

사용자 요청 원문 발췌: “인증 오류 해결해줘”. 비밀값을 공개하지 않고 로컬 키와 워커의 일치를 확인했다.
키가 일치하며 모델 목록 조회 200, 동일 모델의 짧은 생성 요청 200, 제품과 같은 구조의 합성 입력 요청 200을 확인했다.
실제 전사 요청은 403 Access denied로 재현됐다. 직렬화 방식과 불필요한 전사 진단 필드 제거 실험도 실패했다.
이 실험 변경은 제품 코드에 적용하지 않았다. 실패 이력과 호출 기록을 보존했으며 키를 교체하지 않았다.
실제 데이터 요청의 접근 거부 원인은 미확정이다. 모델 출력 품질·후보 생성 성공으로 보고하지 않는다.

키 오류로 단정하던 Groq 403 분류를 PROVIDER_ACCESS_DENIED로 분리했다.
401·명시적 invalid_api_key는 PROVIDER_AUTH를 유지하고 기존 무재시도·유료 대체 없음 계약도 유지한다.
제품 응답에는 정제된 안내만 제공한다. 진단 호출의 관측 사용량은 DB에 기록하며 실제 청구 비용은 알 수 없음이다.
관련 Groq·웹 평가 회귀 검사 49개와 대상 파일 Ruff·서식 검사는 통과했다.
전체 verify는 동시에 작업 중인 별도 사용자 인증 기능 파일의 정적 검사 오류 53개로 중단됐다.
무관한 인증 코드·마이그레이션은 수정하지 않았다. 전체 통합 검사는 이번 오류 분류 변경 후 재실행하지 않았다.
403 오분류는 로컬 코드에서 수정했지만 실제 데이터의 접근 거부 해제는 미완료다.
키·제공자·모델·원문을 임의로 교체하거나 실패 이력을 덮어쓰지 않았다. 로컬 수정은 실행 이미지 재배포를 의미하지 않는다.

## P3 — 120B 거절 원인 추가 분석과 동작 경로 확보

사용자 요청 요약: 해결을 계속하고 120B 요청 거부 원인을 찾는다. 다른 크기의 모델로 전환하지 않는다.
동일한 승인 샘플·키·120B 모델만 사용했으며 추가 진단과 실제 검증은 실행별 승인을 받아 수행했다.

| 대조 실험 | 관측 결과 | 해석 범위 |
|---|---|---|
| 긴 원문을 일반 텍스트로 전송 | 200 | 원문 자체가 항상 거절되는 것은 아님 |
| 20KB 이상 공백 패딩 합성 요청 | 200 | 단순 바이트 크기만의 차단으로 단정 불가 |
| 키 없는 짧은·긴 요청 | 모두 401 | 인증 없는 요청은 정상 인증 오류로 구분됨 |
| 실제 입력의 여러 전송·형식 실험 | 403 재현 | 키 교체·직렬화 변경·SDK 사용만으로 항상 해결되지 않음 |
| SDK·레코드 입력·낮은 추론·2,048 상한·최대 5개 제안 | 전체 후보 생성·채점 성공, 최종 2개 | 해당 프로필의 실제 동작 확인 |
| 같은 연결·모델·스키마·2,048 상한의 A/B | 기존 JSON 200, 후속 레코드 요청 429 | JSON 중첩을 단독 원인으로 지목했던 가설은 기각; 명시적인 토큰 제한도 존재 |

호스트에서만 해결된다는 가설과 JSON 형식이 단독 원인이라는 가설은 후속 실험으로 확정되지 않았다.
403의 정확한 Groq 내부 거절 규칙은 알 수 없다. 계정의 키 인증 자체가 정상이라는 사실과 요청별 접근·한도 제한을 구분한다.
제품 프로필 수정본은 원래 Docker 실행 경로에서도 저장된 전체 전사를 재사용해 후보 생성·채점을 통과했다.
이때 실험용 monkeypatch 없이 제품 어댑터를 사용했다. 원본·전사·기존 실패 이력은 보존했다.
수작업 평가용 고정본에는 실제 후보 2개를 연결하며 사람 판정은 대신 입력하지 않는다.

관련 제공자·분석 파이프라인 회귀 검사 70개 통과. 입력 원문·ID·시간 보존, 진단 메타데이터 제외,
무료 Groq 주소 고정·무재시도·프로필 드리프트 거부·제안 상한·형식 불량 거부를 검사했다.
토큰 사용량은 제공자가 반환한 호출 기록만 사용하며 청구 비용은 알 수 없음이다.

실제 Chrome·FFmpeg를 사용하는 합성 웹 평가 검사 1개도 통과했다. 영상 재생, 선택과 사용 가능 판정의 분리,
저장·새로고침 복원, 모바일 가로 넘침 없음, 영상 Range 206, 자동화 인계 세션 생성을 확인했다.
실제 사용자 평가본에서는 후보 2개·분석 성공·사람 판정 0개·평가 미완료 상태와 영상 Range 206을 확인했다.
기존 후보 없는 평가본과 저장 이력은 보존하고 별도 고정본으로 로컬 평가 서버를 전환했다.
사용자 브라우저 탭 자동 열기는 앞서 도구 정책으로 중단됐으며, 로컬 링크를 통해 직접 열 수 있다.

최종 전체 verify는 현재 별도 인증·업로드 기능 작업 파일의 정적 검사 오류 19개에서 중단됐다.
무관한 파일을 고치거나 검사를 약화하지 않았다. 제품 어댑터 수정은 격리된 실행 스냅샷으로 실제 Docker에서
검증했으며, 동시에 변경 중인 전체 앱의 이미지 재배포·운영 배포·커밋·푸시·Wiki 게시는 하지 않았다.

## P4 — 수작업 평가 영상의 자막 미표시 수정

사용자 요청 원문 발췌: “자막이 안뜨는데”. 평가 페이지에는 영상과 전사 목록만 있고 재생 시각에 동기화한
자막 표시가 없어 발생했다. 고정 전사에서 기존 표시 자막 규칙으로 cues를 계산해 조회 응답에 추가했다.
영상 위 검토용 자막과 전체 문장 박스를 추가하고 표시 토글·탐색·일시정지·발화 사이 공백을 처리했다.
같은 자막을 매 프레임 다시 그리지 않도록 화면 상태가 달라질 때만 DOM을 갱신한다.
단어 시간이 없는 구간은 원래 구간의 전체 문장과 시간을 유지하며, 임의의 단어 경계나 타이밍을 만들지 않는다.
긴 자막은 전체 문장 박스에서 확인할 수 있다. 최종 영상 합성이 아닌 검토용 미리보기다.

실제 서버는 후보 2개·원본 시각 기준 자막 125개·사람 판정 0개를 유지한다.
기존 평가 파일·전사·영상은 덮어쓰지 않았다. 평가 서버만 재시작하고 이전 탭을 닫지 않은 채 새 화면을 열었다.
외부 AI 호출은 없었다. 단위 3개와 실제 Chrome 브라우저 검사 1개가 통과했다.
표시·숨기기, 재생, 자막 없는 구간에서 이전 문장 제거, 다시 탐색했을 때 복원, 평가 저장·복원을 확인했다.
최종 전체 기본 검사는 369개·Ruff·서식·Alembic 오프라인 SQL이 통과했다. 인프라 통합 94개는 기본 검사에서 제외됐고,
이번 변경은 DB·Redis·Celery 계약을 바꾸지 않아 전체 인프라 통합을 재실행하지 않았다. 관련 실제 Chrome 검사는 별도로 통과했다.
사용자 직접 검수는 아직 대기 중이며 Wiki는 미게시다.
