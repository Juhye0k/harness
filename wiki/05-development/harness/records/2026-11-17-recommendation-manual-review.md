# 추천 수작업 평가 웹 연결 — RECO-EVAL-001

> 상태: 작성 중 · 기준일: 2026-11-17

[위키 홈](../../../README.md) · [작업 기록 목차](README.md)

## 요청과 완료 기준

사용자 요청 요약: 검증하고 수작업 평가 웹 페이지를 열며, 평가 후 자동화에 연결한다.
사용자는 기존 승인 샘플의 Groq 무료 추천 1회(후보 생성·채점 각 최대 1회)를 승인했다.
유료 전환·자동 재시도 없이 저장된 성공 전사를 재사용한다.
완료 기준은 실제 후보·영상이 표시되는 페이지와 평가 저장·자동화 인계 데이터 생성, 브라우저 검증이다.

## 시작 상태와 제약

기존 미커밋 변경이 있으며 다른 작업 변경은 보존한다. 실제 DB에는 추천 후보 없이 전사 결과만 있었다.
평가 CLI·반복 실행기는 존재하지만 웹 수작업 평가 화면은 없었다.
사용자의 사람 평가 판정을 대신 입력하지 않는다. 개발 에이전트 사용량·비용은 알 수 없음이다.
기존 [반복 루프 구현 기록](../changes/recommendation-improvement-loop.md)과 연결한다.

## 결과와 검증

웹 평가 저장·복원·저장 충돌·외부 Origin 차단·자동화 인계와 세션 준비의 단위 검사 3개가 통과했다.
로컬 평가 서버는 기동했으나 브라우저 자동 제어가 현재 URL을 신뢰성 있게 확인하지 못해 중단됐다.
실제 추천 후보가 없어 수작업 추천 품질 평가는 미완료다. Wiki 미게시.

## P2 — 인증 오류 해결 요청

사용자 요청 원문 발췌: “인증 오류 해결해줘”. 비밀값을 공개하지 않고 로컬 키와 워커의 일치를 확인했다.
키가 일치하며 모델 목록 조회 200, 동일 모델의 짧은 생성 요청 200, 제품과 같은 구조의 합성 입력 요청 200을 확인했다.
실제 전사 요청은 403 Access denied로 재현됐다. 직렬화 방식과 불필요한 전사 진단 필드 제거 실험도 실패했다.
이 실험 변경은 제품 코드에 적용하지 않았다. 실패 이력과 호출 기록을 보존했으며 키를 교체하지 않았다.
실제 데이터 요청의 접근 거부 원인은 미확정이다. 모델 출력 품질·후보 생성 성공으로 보고하지 않는다.

키 오류로 단정하던 Groq 403 분류를 PROVIDER_ACCESS_DENIED로 분리했다.
401·명시적 invalid_api_key는 PROVIDER_AUTH를 유지하고 기존 무재시도·유료 대체 없음 계약도 유지한다.
제품 응답에는 정제된 안내만 제공한다. 진단 호출의 관측 사용량은 DB에 기록하며 실제 청구 비용은 알 수 없음이다.
관련 Groq·웹 평가 회귀 검사 49개와 대상 파일 Ruff·서식 검사는 통과했다.
전체 verify는 동시에 작업 중인 별도 사용자 인증 기능 파일의 정적 검사 오류 53개로 중단됐다.
무관한 인증 코드·마이그레이션은 수정하지 않았다. 전체 통합 검사는 이번 오류 분류 변경 후 재실행하지 않았다.
403 오분류는 로컬 코드에서 수정했지만 실제 데이터의 접근 거부 해제는 미완료다.
키·제공자·모델·원문을 임의로 교체하거나 실패 이력을 덮어쓰지 않았다. 로컬 수정은 실행 이미지 재배포를 의미하지 않는다.
