# 실제 영상으로 입력·추천·편집 흐름 확인 — REAL-FLOW-001

**두 패널에서 누락 자막 6구간의 문구 초안 23개를 준비하고, 실행 코드·원본 보존·출력 전 조건을 재확인했다.** 저장본은 아직 원음 미확정이므로 최종 MP4·SRT 출력과 그 결과 검증은 수행하지 않았다. 아래에서 완료한 준비와 남은 확인을 구분한다.



실제 영상과 보존한 AI 추천 결과를 최신 웹 서비스에 연결해 입력부터 자막 편집까지 확인한다. 원음 확인이 필요한 자막은 사람이 검수하기 전까지 출력하지 않는다.

## 무엇을 확인하는가

합성 테스트가 통과해도 실제 전사의 시간 정보가 부족하면 자막을 바로 출력할 수 없다. 이번 작업은 승인된 기존 영상과 실제 Groq 추천 결과를 재사용해 그 차이를 확인한다.

사용자 요청 요약: 남은 1·2·3번을 별도 워크트리로 진행하고, 검증 후 PR·main 병합·Wiki 게시 결과를 보고한다. 이 기록은 그중 3번인 실제 영상 전체 흐름 검증을 다룬다.

완료 기준은 실제 파일 업로드·검증, 보존한 실제 추천 후보 조회, 후보 선택·자막 편집 저장, 원음 확인 상태에 따른 출력 허용/차단과 결과 다운로드 확인이다. 실제 SNS 게시·새 유료 모델 호출은 포함하지 않는다.

## 어떻게 진행하는가

1. 원본 해시와 길이를 확인하고 새 개발 환경에 파일을 업로드한다.
2. 기존 실제 모델 결과를 새 자산에 복사한다. 새 모델 호출로 만든 결과라고 표시하지 않는다.
3. 추천 후보를 선택하고 원본 전사·단어 시간·자막 초안을 확인한다.
4. 미확정 자막을 저장하고 출력이 차단되는지 확인한다.
5. 사람이 원음과 자막을 확인하면 해당 버전으로 영상을 출력하고 MP4·SRT를 검사한다.

개발 환경은 별도 DB·파일 볼륨을 사용하는 로컬 서비스다. 기존 DB·사용자 원본은 변경하지 않는다.

## 실행 기준과 현재 제약

시작 코드는 `1818e5c`이며 검증 브랜치는 `verify/real-flow-20261118`이다. 기존 원본은 404.237초이며 고정 전사에는 121개 구간, 실제 추천 결과에는 후보 2개가 있다.

두 후보의 자동 자막은 모두 검수가 필요하다. 후보 1은 원 구간 8개 중 2개에, 후보 2는 7개 중 1개에만 단어 시간이 있다. 부족한 단어 시간을 균등 분배로 만들어 채우거나 사람 검수 완료를 대신 입력하지 않는다.

## 결과와 검증

**실제 파일을 업로드하고 보존한 추천 후보를 선택해 편집본을 저장했다. 원음 확인 전 출력은 화면과 서버에서 모두 차단됐다.** 새 모델 호출 없이 기존 실제 결과를 사용했으며, 실제 인식 정확도와 추천 적합성에 대한 사람 평가는 아직 없다.

| 확인한 단계 | 관측 결과 | 의미 |
|---|---|---|
| 실제 파일 업로드 | 23,929,026바이트·404.237초, POST 1회·PUT 1회 | 합성 파일 대신 기존 실제 원본을 사용 |
| 업로드 후 새로고침 | 추가 POST·PUT 0회 | 원본을 다시 전송하지 않음 |
| 실제 결과 재사용 | 전사 121개·추천 후보 2개 | 기존 Groq 결과의 복사이며 신규 모델 호출 성공은 아님 |
| 원본 미리보기 | 1280×720, 실제 재생 시각 진행·Range 206 | 편집 화면에서 선택 구간을 재생할 수 있음 |
| 자동 자막 점검 | 후보 1은 미확인 원 구간 6개, 후보 2도 6개 | 긴 문장을 자동으로 잘라 시간을 만든 것처럼 처리하지 않음 |
| 편집·저장 | 시간 정보가 있는 자막 9개를 부분 초안으로 저장 | 문장부호 수정을 반영했으며 확인 상태는 false |
| 저장 후 새로고침 | 같은 편집 버전 복원·추가 POST 0회 | 저장 결과를 재사용 |
| 미확정 출력 요청 | 버튼 비활성·서버 409 `SUBTITLE_REVIEW_REQUIRED` | 화면을 우회해도 검수 전 최종 출력 불가 |
| 외부 부작용 | 새 provider_calls 0개·SNS 업로드 0개 | 추가 AI 호출·SNS 게시 없음 |

부분 초안을 저장하기 전에는 자동 초안의 긴 문구·시간을 그대로 저장하려는 요청이 거절됐다. 길이 규칙을 약화하지 않고, 시간 정보가 검증된 자막만 미확정 상태로 저장했다. 빠진 원 구간의 원문은 편집 화면에 보존돼 있으며 사람이 자막을 추가하고 시각을 확인해야 한다.

별도로 같은 원본의 5초 지점부터 **10초 추출·다운로드**도 확인했다. 길이·영상 트랙·음성 유지·전체 디코딩·원본 보존 검사를 모두 통과했다. 이 출력은 자막을 확정한 최종 숏폼이 아니므로 최종 단계의 완료 증거로 사용하지 않는다.

실행 코드의 앱 해시는 `8ed6682fec350f36669c8cced80f4902b451d3fe2056e5f9187045bd454d48e7`이다. 원본 SHA-256은 업로드 전후와 추출 후 모두 `05ca5b16767257d6bf0590e0a0916b3f2a36623f71984549019870c5bad24d06`로 같았다. 개발 도구의 초기 실행 경로·텍스트 인코딩 오류는 바로잡았고, 제품 코드나 검사 기준은 변경하지 않았다.

브라우저 trace·스크린샷·요청 수·DB 관측·검수할 원문은 로컬 비공개 산출물에 보관했다. 실제 원본·전사·검수용 trace는 Git과 Wiki에 올리지 않는다.

별도 워크트리에서 `uv run --no-sync python scripts/verify.py`도 실행했다. 기존 잠금 파일과 같은 공유 개발 가상환경을 사용해 Ruff·서식·기본 **375개**·Alembic 오프라인 SQL이 통과했고 통합 107개는 제외됐다. 첫 실행은 pytest 임시 경로의 부모 디렉터리가 없어 준비 단계에서 실패했으며, 경로를 만든 뒤 같은 코드를 재검사했다. 기존 Starlette/httpx 사용 중단 예정 경고 1건이 남는다. 새 문서의 상대 링크 2개와 diff 공백 검사도 확인했다.

## 두 패널의 결과를 합친 후속 확인

사용자는 자막 보완과 출력 검증을 현재 탭의 별도 패널에서 진행하고, 결과를 주 대화로 합친 뒤 PR·main 병합·Wiki 반영까지 진행하도록 요청했다. 위 패널은 자막 초안, 아래 패널은 출력 전 검사를 담당했다. 후속 진행 요청에 따라 완료한 준비·재점검 근거를 문서로 반영하며, 실제 출력 완료로 표시하지 않는다.

| 담당 | 실제 수행한 일 | 결과와 제한 |
|---|---|---|
| 위: 자막 보완 | 원 구간 6개의 문구를 23개 자막 초안으로 분할하고 원음 재생 자료 준비 | 원문·순서·1~3어절·한 줄 14자 이하 확인. 개별 시작·끝 시각은 미지정 |
| 위: 사용자 편집 보존 | 최신 편집본을 다시 조회하고 기존 9개 자막과 비교 | 기존 내용과 버전 보존. 서버 자막 저장·출력 접수 0회 |
| 아래: 실행 대상 확인 | API·워커가 실제 사용하는 경로와 관련 파일 8개의 해시 확인 | 기존 런타임 코드와 일치. 다른 패널의 root 변경과 구분 |
| 아래: 입력·구간 확인 | 서버가 제공한 원본의 해시와 후보 시작·끝 확인 | 기존 원본 해시 동일, 후보 59.36~91.68초·길이 32.32초 |
| 아래: 출력 조건 확인 | 최신 버전의 원음 확인 상태와 원 구간 연결 확인 | `reviewed=false`, 8개 중 2개만 연결, 출력 작업 없음 |

자막 초안의 **문구 분할 검사**와 **타이밍 검사**는 다르다. 개별 시각을 확인하지 않았으므로 0.45~1.8초 표시·15자/초 읽기 속도·자막 겹침을 통과했다고 기록하지 않는다. 검토 자료에서 듣는 것과 서버 편집본을 확정해 저장하는 것도 별개다.

### 아직 실행하지 않은 검사

확정본이 없으므로 영상 출력 접수, 최종 MP4 길이·720×1280·필수 트랙·전체 디코딩, 같은 버전 SRT의 문구·줄바꿈·클립 시각, 출력 파일 해시·버전 연결, 렌더 후 원본 보존과 대표 프레임의 한글·여백 검사는 미실행이다. 다른 10초 추출이나 과거 합성 검사를 이번 완성본의 성공으로 대신하지 않는다.

### 근거와 공개 범위

두 패널의 최종 응답, 최신 편집 API, 비공개 상태 JSON과 재점검 보고서를 대조했다. 원음·원문·문구 초안·전체 실행 로그·개인 경로는 공개하지 않고, 위의 관측값과 제한만 기록한다. 새 제품 AI 호출·SNS 게시·원본 삭제·제품 코드 변경은 없다.

원래 root 폴더의 기본 검사는 다른 작업 파일의 Ruff 줄 길이 오류 3건에서 중단된 기록이 있다. 이를 숨기거나 무관한 코드를 수정하지 않는다. 이번 문서 반영은 최신 main의 별도 브랜치에서 검사하며, 서로 다른 코드 상태의 결과를 혼동하지 않는다.

후속 문서 브랜치는 main `0ea3d06`에서 시작했고 제품 코드는 변경하지 않았다. `uv run python scripts/verify.py`의 Ruff·서식·기본 375개·Alembic 오프라인 SQL이 통과했다. 통합 107개는 기본 검사에서 제외됐으며 PR의 필수 CI는 해당 커밋으로 별도 확인한다. 문서 3개의 상대 링크 35개, diff 공백, 민감정보 패턴과 한글 인코딩도 확인했다.

## 다음에 사람이 확인할 것

첫 후보의 원본 구간은 59.36~91.68초다. 이 중 65.56~76.46초와 81.46~91.48초에 단어 시각이 없는 원 구간 6개가 남아 있다. 편집 화면에서 원본 전사를 펼치고 해당 부분을 들어 자막 문구·분할·시각을 보완해야 한다.

모든 원 구간을 확인한 뒤 사용자가 원음 확인 항목을 선택하고 저장하면, 그 불변 버전으로 최종 세로 MP4와 SRT를 출력·검사한다. 이번에는 확인 항목을 대신 선택하지 않았으며 최종 MP4·SRT 다운로드도 아직 수행하지 않았다. 추가 모델 호출 없이 진행했으므로 최신 서비스에서의 신규 AI 분석 성공 여부도 이번 검사 범위 밖이다.

사용자는 웹에서 직접 자막을 수정하고 원음을 확인하겠다고 응답했다. 이는 검토를 진행하겠다는 의사이며 자막 검수 완료로 기록하지 않는다. 검토할 서비스와 편집본은 유지한다.

## 사람과 AI의 역할

사용자는 동일 영상·무료 제공자와 실제 흐름 검증을 선택했다. AI는 데이터 보존·연결·업로드·편집·서버 검증을 수행한다. 원음과 자막의 일치, 추천의 유용성은 사람 확인으로 남긴다. 개발 에이전트 사용량·비용은 도구가 제공하지 않아 알 수 없음이다.
