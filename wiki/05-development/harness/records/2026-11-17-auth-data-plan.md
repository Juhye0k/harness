### 구현 시 선택과 제한

- 승인 전 사용자는 pending이며 운영자 CLI로만 승인한다. 기존 로컬 원본·평가 자료·SNS 토큰은 자동 이전하지 않는다.
- 새 소유 자료는 7일 보관하며 만료를 API가 즉시 차단한다. 삭제는 DB 접수 후 파일·민감 내용 순서로 정리하고 완료를 기록한다.
- 요청·다운로드·워커의 사용 기록은 정상 종료 시 해제한다. 강제 중단 후에는 운영자 확인 전 정리를 보류한다. 첫 버전은 사용자 단위로 보수적으로 정리를 보류한다.
- 자동 업무 재실행은 추가하지 않았다. 만료·탈퇴로 실행할 수 없어진 pending/queued 작업만 외부 호출 없이 종결한다. running·unknown SNS는 확인 전 보존한다.
- API의 읽기 전용 파일 볼륨은 유지하고 cleanup 프로필을 별도로 추가했다. 종료한 삭제 이력은 30일 후 정리하며 내용 없는 자료 표식·내부 ID는 남는다.
- Google 로그인 설정·실계정 OAuth·운영 백업과 복구·기존 서비스 전환은 검증하지 않았다. 인증 기본값 false는 로컬 호환용이고 development/test 외에서는 인증 없이 요청을 받지 않는다.

사용자는 로그인 클라이언트·콜백 등록을 에이전트에게 위임했다. 최초 브라우저 조작은 사용자의 Escape 입력으로 끝났고, 후속 두 차례는 현재 URL 확인 실패로 도구가 중단했다. 재연결 후 기존 harness 프로젝트의 Google 인증 플랫폼에 접속해 테스트 사용자 2명과 SNS 전용 클라이언트 1개를 확인했다. 로그인 전용 웹 클라이언트 `Shortform Google Login local verification`와 콜백 `http://localhost:8002/auth/google/callback`을 생성 양식에 입력했다. 새 영구 인증 정보 발급 직전 브라우저 도구의 확인 규칙에 따라 사용자 확인을 요청했으며, 이 기록 시점에는 아직 생성하지 않았다.

### P11~P12 — 키 발급 승인과 실제 로그인 진행

입력 표기: 같은 대화의 후속 요청 원문 발췌.

> 계속진행해
>
> 계쏙해

사용자가 키 발급과 검증 계속 진행을 승인했다. Google Cloud에서 로그인 전용 클라이언트 생성 완료 화면과 등록된 로컬 콜백을 확인했고, 발급 직후 JSON을 다운로드해 승인된 클라이언트·프로젝트·콜백 일치를 검증한 뒤 Git 제외 대상인 `.env`에 로그인 전용 ID·비밀값만 반영했다. 비밀값은 이 기록·소스 코드에 저장하지 않는다. 포트 8002 API만 재생성했고 기존 개발 서비스·DB·SNS 설정은 변경하지 않았다.

검증 API의 `/auth/google/start`는 HTTP 307, 대상 `accounts.google.com`, 콜백 `http://localhost:8002/auth/google/callback`, 권한 `openid email`, PKCE `S256`, 임시 로그인 쿠키 `HttpOnly`를 확인했다.
