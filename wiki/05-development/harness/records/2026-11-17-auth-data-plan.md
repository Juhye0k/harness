## 문제와 완료 기준

최초 요청은 사용자 인증·자료 관리 계획 수립이며 후속 P5에서 구현까지 범위를 확대했다. 계획의 완료 기준은 현재 코드에 근거한 변경 지점·순서·정책·검사·미결정 항목의 구분이다. 구현의 완료 기준은 Google 로그인 경계·사용자 격리·7일 보관·삭제의 자동 검사이며 실제 계정 연동·기존 사용자 자료 삭제·운영 배포는 포함하지 않는다.

## 시작 상태와 관측 정보

- 시작 커밋: `0167efd63d57196b34a80f16ab64aa8ce9773ef8`. 제품·문서·검사의 기존 미커밋 변경을 보존했다. 시작 커밋만으로 현재 코드 상태를 재현할 수 없다.
- 종료: 미커밋. 실행 환경은 Windows PowerShell, Git과 문서 검색 도구다. 버전은 별도 수집하지 않았다.
- 개발 에이전트: Codex. 정확한 실행 모델 버전·사용량·비용·전체 소요 시간은 알 수 없음.
- 제품 외부 AI·SNS 호출: 이번 계획 수립에서 실행하지 않음. 공식 Google·OWASP 문서는 읽기 전용으로 확인했다.

## 프롬프트와 결과

### P1 — 계획 수립

입력 표기: 현재 요청 원문 발췌. 비식별 처리할 값은 없었다.

> 4번 어떻게 진행할지 계획 수립해줘

4번은 직전 작업 목록의 사용자 인증·데이터 관리다. 에이전트는 models·영상/분석/검수/검증/SNS API·저장소·현황·운영 문서를 읽고 [계획](../../../03-architecture/user-auth-data-management.md)을 작성했다. 구현 코드와 사용자 데이터는 변경하지 않았다.

### P2 — 로그인 방식 선택

입력 표기: 사용자가 선택한 응답 원문 발췌.

> Google 로그인: 비밀번호 관리 없이 시작 (권장)

로그인은 Google OIDC로 확정했다. 서버 세션·소유권·자료 보관·삭제 절차는 에이전트의 설계 제안이며, 보관 수치는 사용자가 확정한 정책으로 표현하지 않는다.

## 사람의 판단과 AI의 작업

### P3~P5 — 구체화와 구현 요청

입력 표기: 현재 대화의 요청 발췌 및 선택 응답 요약. 개인 자료·비밀값은 포함하지 않았다.

> 구체적으로 각 단계가 왜 필요한지 어떻게 구현할건지 계획 세워줘.

사용자는 보관 정책으로 **7일 후 자동 삭제**, 초기 대상으로 **지정한 테스트 계정**을 선택했다. 에이전트는 각 단계의 필요성·자료 구조·세션·소유권·삭제·검증을 구체화했다.

> Implement the plan.

이 요청에 따라 [실행 안내](../../user-auth-data.md), [auth API](../../../../app/api/auth.py), [소유권·사용 기록](../../../../app/services/access.py), [정리 프로세스](../../../../app/cli/cleanup_data.py), migration 0005, 로그인·내 자료 화면과 회귀 검사를 추가했다. 기존 API와 워커에 공통 인증·자료 사용 경계를 연결했다. 공식 토큰 검증을 위해 google-auth[requests]와 uv.lock을 함께 갱신했다.

작업 시작 시 기존 미커밋 변경을 확인하고 보존했다. 같은 작업 폴더에서 인증 관련 부분을 추가했으며 별도 브랜치·커밋·원격 게시를 생성하지 않았다. 개발 DB와 서비스는 전환하지 않고 폐기 가능한 별도 PostgreSQL과 격리 통합 Compose에서만 migration·자료 삭제를 실행했다.

### 구현 시 선택과 제한

- 승인 전 사용자는 pending이며 운영자 CLI로만 승인한다. 기존 로컬 원본·평가 자료·SNS 토큰은 자동 이전하지 않는다.
- 새 소유 자료는 7일 보관하며 만료를 API가 즉시 차단한다. 삭제는 DB 접수 후 파일·민감 내용 순서로 정리하고 완료를 기록한다.
- 요청·다운로드·워커의 사용 기록은 정상 종료 시 해제한다. 강제 중단 후에는 운영자 확인 전 정리를 보류한다. 첫 버전은 사용자 단위로 보수적으로 정리를 보류한다.
- 자동 업무 재실행은 추가하지 않았다. 만료·탈퇴로 실행할 수 없어진 pending/queued 작업만 외부 호출 없이 종결한다. running·unknown SNS는 확인 전 보존한다.
- API의 읽기 전용 파일 볼륨은 유지하고 cleanup 프로필을 별도로 추가했다. 종료한 삭제 이력은 30일 후 정리하며 내용 없는 자료 표식·내부 ID는 남는다.
- Google 로그인 설정·실계정 OAuth·운영 백업과 복구·기존 서비스 전환은 검증하지 않았다. 인증 기본값 false는 로컬 호환용이고 development/test 외에서는 인증 없이 요청을 받지 않는다.

### 구현 검사

- 전용 PostgreSQL에 migration 0005 적용 성공. A/B 사용자 교차 접근, 원본 재사용·SNS 입력 거부, 세션·CSRF·로그아웃, 삭제 중 접근 차단·중복 접수·정리, 만료·기존 자료 보존, 탈퇴 제한 조회, 로그인 승인·콜백 재사용, 실제 Range 다운로드를 확인했다.
- 실제 Edge를 포함한 인증 전용 통합 **17개 통과**. 계정 전환 시 이전 localStorage 제거·로그인 전 접근 제한·로그아웃 후 재접근 차단을 확인했다. 토큰 검증 오류 전파·nonce·재인증과 경로 경계 단위 **7개 통과**.
- 최초 기본 검사에서는 pytest 공용 임시 폴더 권한 오류로 129개 setup 오류가 발생했다. 작업 전용 basetemp로 재실행해 당시 기본 **338개**, Ruff·서식·Alembic SQL 통과.
- 최종 `uv run python scripts/verify.py`: **345개 통과·통합 81개 제외**, Ruff·서식·Alembic SQL 통과. `PYTEST_ADDOPTS`로 작업 전용 basetemp와 cacheprovider 비활성화를 지정했다.
- 최종 Linux PostgreSQL·Redis·Celery·FFmpeg·Chromium 통합: **81개 통과**, 이 중 인증 전용 17개를 포함한다. 외부 Google·AI·실계정 SNS는 대역으로 대체했다. 기존 Starlette/httpx 사용 중단 예정 경고 1개가 남는다.
- 실행 문서·설계·기록·목차·결정 문서의 상대 링크 **41개** 존재 확인, `git diff --check` 통과. 검사 후 shortform-integration 전용 컨테이너·영상 테스트 볼륨·네트워크와 전용 PostgreSQL 컨테이너 shortform-auth-test·테스트 볼륨을 정리했다. 기존 개발 Compose와 DB는 유지했다.
- Linux 이미지는 기존 의존성 빌드를 사용하고 최종 app·tests·scripts·migrations를 읽기 전용으로 마운트해 검사한다. 실제 Google·AI·YouTube 호출이나 사용자 원본 전송은 하지 않는다.

- 사용자: Google 로그인·7일 보관·테스트 계정 범위를 선택하고 구체화한 계획의 구현을 요청했다.
- AI: 현재 코드의 사용자 경계를 조사하고 migration·로그인·API 소유권·삭제 처리를 구현하고 검사했다.
- 사용자 직접 구현·실계정 결과 검수: 확인되지 않음.

## 초기 계획 수립 당시의 검사 이력

아래는 구현 요청 전의 결과다. 현재 구현 결과는 위의 ‘구현 검사’를 따른다.

| 확인 항목 | 관측 결과 |
|---|---|
| 문서 링크 | 수정·추가한 5개 문서의 상대 링크 36개를 PowerShell로 검사. 모두 대상 존재 |
| 문서 내용·공백 | 현재 models·API·저장소의 소유권 부재와 SNS 브라우저 세션 구조를 대조. `git diff --check` 통과 |
| 기본 검사 | `uv run python scripts/verify.py` 최초 uv 캐시 권한 오류 뒤 승인된 환경에서 재실행. 다른 작업에서 작성 중인 `scripts/review_recommendations.py`의 Ruff F401 1건·E501 5건으로 중단 |
| 미실행 검사 | 기본 검사가 첫 단계에서 종료해 서식·pytest·Alembic SQL은 미실행. 계획 작성이므로 실제 인프라 통합·신규 업무 테스트·DB migration·실제 로그인·자료 삭제는 실행하지 않음 |

계획 단계에서는 일반 CI와 실제 Google 로그인 검증을 구분했다. 위 당시 오류를 이유로 다른 진행 중인 코드를 수정하지 않았다.

## 포트폴리오용 요약 초안

단일 개발 환경의 영상 서비스를 사용자별로 분리하기 위해 Google 로그인·승인 계정·서버 세션·자료별 소유권과 7일 보관·삭제를 구현했다. 사용자는 로그인 방식·보관 기간·초기 대상을 정했고 AI는 API·파일·SNS·워커의 사용자 경계를 연결했다. 기존 자료를 자동 귀속하지 않고 요청·워커·다운로드 사용 상태와 정리를 조정했다. PostgreSQL과 실제 브라우저에서 격리·삭제·로그아웃을 확인했으며 실제 Google 계정·운영 보안성·성능은 별도 검증 대상이다. 시간 절감률이나 사고 방지율은 측정하지 않았다.
