# 편집 완료본의 YouTube 게시 검증

> 복구된 SNS 서비스에서 준비 응답과 세션·출처·요청 위조 방지·명시적 게시 확인의 거부 규칙을 검증했다. 기존 계정과 업로드 이력은 보존됐으나 소유자 브라우저 세션은 미확인이다. 실제 편집본의 원음 확인·파일 인수·게시 승인과 추가 실영상 평가가 남아 있다.

## 요청 및 완료 기준

| 단계 | 확인할 근거 |
| --- | --- |

| 완료 기준 | CI 필수 검사에 통과한 결합 코드로 원음 확인된 34개 자막 편집본을 출력한다. 같은 바이트의 미리보기와 승인값을 확인하고, 실제 전송 후 원격 메타데이터·처리 완료·Studio Shorts 분류를 검사한다. 사용 승인과 참조가 있는 독립 영상으로 품질을 평가한다. 최신 사용자 지시에 따라 완료된 검증 결과의 main·Wiki 반영과 실제 게시 대기는 구분한다. |

시작 기준은 `12673d8`이며 전용 작업 트리는 깨끗했다. 원래 작업 트리에는 기존 변경이 있었다. Codex에서 읽기 전용 HTTP 점검, Node.js 실행 환경, Herdr 인수를 사용했다. 개발 에이전트 사용량과 비용은 미제공이다.

## 수행 및 검증 근거

| 검사 | 결과 |
| --- | --- |
| 로컬 SNS 화면·세션 | 화면과 세션 HTTP 200, 기능 활성화 응답 확인. 다른 출처는 403, SNS 세션 없이 계정 조회는 401. |
| 실제 의존 서비스 | 양쪽 포트의 준비 상태와 새 세션의 계정 조회가 503. 준비 응답은 PostgreSQL·Redis를 사용 불가로 표시했다. 채널 소유자 세션은 미확인이다. |
| JavaScript 대역 | 미리보기 응답 유실 뒤 같은 요청 ID를 유지하고, 만료 후 사용자가 편집을 선택하면 새 초안 ID를 사용했다. 서버 SHA-256과 같은 작업의 다운로드 경로가 화면에 나타났으며, 명시적 확인 체크 없이 게시 확인 요청이 나가지 않았다. |
| SNS·YouTube 단위 검사 | 전용 트리에서 기존 잠금 환경으로 단위 검사 42개를 통과했다. 사용 중단 예정인 테스트 클라이언트 연동 경고 1건이 있었다. |
| 추가 자료 확인 | 비교 기록의 후보 둘은 모두 같은 영상이다. 다른 바이트의 과거 추출 검사용 원본 두 종류를 발견했으나, 자막 평가용 참조나 전사와 현재 사용 범위를 확보하지 못했다. |
| 전체 기본 검사 | Ruff 검사와 포맷 확인 통과. pytest 400개 통과, 1개 실패, 4개 설정 오류, 통합 영역 107개 제외. 4개 오류는 한글 폰트 복사 중 디스크 공간 부족으로 발생했고, 오프라인 예제 하나는 `IO_FAILED`를 반환했다. |
| 미실행 | 필수 CI가 끝난 결합 런타임의 실제 계정·브라우저·출력 검사는 인수 대기 중이다. 3번의 추가 합성 매체 네 종류는 별도의 렌더 호환성 근거로 인수했다. |

이전 승인으로 합성 세로 영상의 비공개 업로드와 Studio Shorts 분류를 확인한 기록이 있다. 이번 편집본은 실제 채널 미리보기나 전송 시도가 없었다.

## 실제 검증 절차

1. 결합 PR head를 개발 런타임 담당에게 인수하고 8001 준비 상태, 기존 OAuth 콜백과 전용 큐 보존을 확인한다. 채널 소유자가 기존 브라우저에서 연결 상태를 확인하고 필요할 때 직접 로그인·동의한다.
2. E2E 담당의 사람 확인 버전 ID, 출력 작업 ID, MP4 SHA-256을 확보한다. SNS 초안의 승인 해시와 작업 다운로드의 해시를 각각 비교한다. 채널 이름과 ID, 제목, 공개 범위, 아동용 설정을 포함한 동일한 제안을 사용자에게 보여 준다.
3. 정확한 미리보기 승인 뒤 업로드를 한 번 요청한다. 응답이 사라지면 기존 업로드 ID를 조회한다. 미확정이면 저장된 세션 상태를 조회한 뒤, 원격 메타데이터·처리 성공·Studio 분류를 각각 기록한다.

## 다른 실제 입력 평가

| 기록할 것 | 판정 근거 |
| --- | --- |
| 원본 영상·전사·고정 조건 | 승인된 로컬 원본의 SHA-256, 후보 구간, 전사·단어 시간과 설정 버전을 먼저 고정한다. 원본 자막, 자막색·배경, 말 속도, 음악·겹침 음성 조건을 기록한다. |
| 자막·추천 | 사람이 확인한 화면 구간과 문구를 기존 평가 도구에 넣고 전체·구간별로 기록한다. 편집 SRT에서 어절·순서 보존, 표시 시간·겹침, 영상 음성과 문맥 연결을 확인한다. |
| 미평가 범위 | 수동 검증된 화면 구간만 화면 자막의 존재 근거로 사용한다. 참조 없이 남은 구간은 미평가로 두고, 정답 전사가 없는 영상의 실제 음성 CER(글자 오류율)는 미확인으로 기록한다. 고정 기준은 새 영상 결과에 맞춰 바꾸지 않는다. |
| 실행과 원본 보존 | 로컬 FFprobe로 길이·트랙을 확인하고 FFmpeg 디코딩과 전후 원본 해시 비교를 한다. `scripts/evaluate_source_captions.py`의 `--ocr`, `--editor`, `--reference`, `--output`을 사용한다. 새 모델 호출과 외부 영상 전송은 필요하지 않다. |

## 작업 인수와 상태

채널 접근·정확한 업로드 승인과 추가 영상 사용 범위는 사용자 결정이다. 실행 런타임은 1번 담당이다. 기존 코드는 PR #15로 병합됐고 후속 검증 기록의 main·Wiki 반영은 [재개 기록](2026-11-19-flow-resume.md)과 완료 보고에서 확인한다. 실제 게시와 추가 장르 검증은 대기 중이다.

## 재개 요청 (2026-11-19)

기존 작업 트리 `1d2b543`과 PR #15의 병합본 `45739f4`를 기준으로 SNS와 추가 실영상 검증을 재개한다. 기존 CI와 SNS 검사 결과를 재사용한다. 런타임은 1번이 복구하며, 5번의 이 단계는 8001에서 계정·콜백·미리보기 보호 규칙을 확인하고 4번의 원음 확인된 버전·작업·파일 해시를 인수할 준비까지 진행한다. 별도 실제 영상은 승인된 로컬 원본과 참조가 있을 때 평가한다.

### 전용 패널 재검증

역할 5 트리 `1d2b543`에서 `uv run --no-sync python scripts/verify.py`가 종료 코드 0으로 끝났다. Ruff, 포맷, 기본 테스트 405개와 0008까지의 마이그레이션 SQL 생성을 확인했다. 첫 실행의 pytest 임시 디렉터리 권한 오류는 전용 디렉터리를 지정해 해소했다. 최종 실행에는 테스트 클라이언트 사용 중단 예정 경고와 pytest 캐시 쓰기 경고가 각 1건 있었다. 통합 테스트 107개는 기본 검사에서 제외됐다.

호스트에서 8001과 8003의 준비 상태를 직접 요청했으나 두 포트 모두 연결을 거부했다. 4번 인수 기록의 원음 확인 버전, 작업 번호, MP4·SRT 해시는 비어 있었다. 따라서 이번 편집본의 계정·콜백·미리보기·게시 결과는 미검증이다. 이번 회차의 게시 시도, 유료 호출, 외부 미디어 전송은 모두 0건이다.

고정 전사 원본의 해시가 기존 기준과 일치했다. 보관된 추출 원본 5개는 해시 기준 두 종류였고, 추출 보관 폴더에서 대응 전사나 자막 참조를 찾지 못했다. 추가 실영상의 로컬 경로와 평가 사용 허용 범위, 보유한 참조자료 경로를 요청했다. 이번 재검증 내용은 로컬 Wiki 원본에만 반영했다.

### 복구 후 실제 SNS 서비스 확인

역할 1이 main `45739f4`와 DB 버전 `0009_caption_render_jobs`를 인계한 뒤 8001·8003에서 PostgreSQL·Redis 준비 상태 HTTP 200을 직접 확인했다. 8001 SNS 화면과 세션도 200이었고, 초기 게시 버튼은 비활성 상태였다. 기존 OAuth 설정과 콜백 주소가 적용돼 있었으며 상태값 없는 콜백은 로컬 오류 화면으로 303 응답했다. 세션 누락은 401, 다른 출처와 요청 위조 방지 토큰 누락은 각각 403, 명시적 확인 누락은 422로 거부했다.

역할 1이 확인한 DB에는 연결 계정 1개와 과거 업로드 1건이 있었고, 새 점검 세션의 계정 목록은 0개였다. 브라우저 연결 도구가 응답하지 않았고 최소화된 Chrome 창에서 소유자 세션을 확인할 수 없었다. 소유자 브라우저의 채널 확인과 사람이 원음을 확인한 34개 자막 버전의 출력 인수를 기다린다. 이번 파일의 실제 미리보기·게시 시도는 0건이다.
