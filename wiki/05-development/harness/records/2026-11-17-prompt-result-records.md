## 문제와 완료 기준

기존 하네스에는 실패·개선 기록과 최소 기록 규칙이 있었지만, 사용자 프롬프트와 대응 결과를 작업별로 남겨 포트폴리오에 옮기는 공통 양식은 없었다. 이번 범위는 기록 절차·양식·실제 첫 사례를 문서로 연결하는 것이다.

완료 기준은 시작·종료 절차와 리뷰에서 기록을 확인할 수 있고, 프롬프트·결과·사람과 AI의 기여·검증 근거·한계를 같은 페이지에서 확인할 수 있는 것이다. 원격 게시 상태도 별도로 표시한다.

## 시작 상태와 실행 정보

- 시작 커밋: `0167efd63d57196b34a80f16ab64aa8ce9773ef8`. 기존 제품 코드·검사·문서의 미커밋 변경이 있어 보존했다. 이 커밋만으로 현재 작업 폴더가 재현되지는 않는다.
- 종료 버전: 미커밋. 커밋·PR·원격 푸시는 수행하지 않았다.
- 실행 환경·도구: Windows PowerShell, Git, uv, 저장소 공통 검사 진입점. 도구 버전은 별도 수집하지 않았다.
- 개발 에이전트: Codex. 정확한 실행 모델 버전·사용량·비용·전체 소요 시간은 알 수 없음.
- 제품 외부 AI 호출: 이번 문서 작업에서 실행하지 않음. 개발 에이전트 비용을 0으로 의미하지 않는다.

## P1 — 사용자 요청과 결과

입력 표기: 현재 요청의 원문 발췌. 비식별 처리가 필요한 값은 없었다.

> 내가 입력하는 프롬프트와 얻은 결과를 wiki에 정리해서 추후에 포트폴리오에 써먹을 수 있게 정리하고 싶어. 해당 내용을 하네스에 반영해줘

요청 의도는 작업 지시와 실제 결과를 재사용 가능한 개발 근거로 남기는 것이다. 에이전트는 [기록 절차·목차](README.md)와 [양식](template.md)을 추가하고, [AGENTS.md](../../../../AGENTS.md)·[작업 절차](../workflow.md)·[완료 기준](../review.md)·[PR 양식](../../../../.github/pull_request_template.md)에 연결했다. 개발·하네스·Wiki 목차와 [문서 작성 규칙](../../../07-governance/document-guide.md)에도 진입점을 추가했다.

에이전트가 작업 중 기록을 작성·갱신하는 방식이며 대화 자동 수집이나 자동 게시 기능을 추가한 것은 아니다. 기존 과거 작업의 프롬프트를 추정해 채우지 않았다.

## 사람의 판단과 AI의 작업

- 사용자: 프롬프트와 결과를 Wiki에 축적하고 포트폴리오 근거로 사용한다는 목적을 정했다.
- AI: 기존 기록 구조를 조사하고, 작업별 기록 양식·프롬프트와 결과 연결·기여 구분·검증 및 게시 상태 표기를 설계해 문서를 수정했다.
- 사용자 직접 구현·결과 검수: 현재 대화에서 확인되지 않음. 위 세부 방식을 사용자가 직접 설계한 것으로 기록하지 않는다.

## 검증과 남은 제한

| 검사 | 실행·관측 결과 |
|---|---|
| 문서 링크 | 수정·추가한 11개 문서의 상대 링크 127개를 PowerShell로 추출해 대상 존재 여부 확인. 모두 존재 |
| 변경 검토 | `git diff --check` 통과. 하네스 지침·절차·양식 diff와 새 기록의 내용 검토 |
| 공통 기본 검사 | `uv run python scripts/verify.py` 실행. 최초 uv 캐시 권한 오류 후 승인된 환경에서 재실행. Ruff 코드 검사 통과, 서식 검사에서 중단 |
| 서식 실패 | 다른 작업에서 변경 중인 [evaluate_recommendations.py](../../../../scripts/evaluate_recommendations.py)의 `reasons` 타입 선언과 비교 입력 읽기 구문이 Ruff 서식과 불일치. 이번 문서 작업에서 수정하지 않음 |
| 미실행 검사 | 공통 검사가 첫 실패에서 종료해 pytest·Alembic 오프라인 SQL은 실행되지 않음. 이번 변경은 문서뿐이므로 실제 인프라 통합 검사·영상 품질 평가·외부 AI·SNS 검사는 실행하지 않음 |

기록 양식과 작업 절차의 연결은 확인했다. 전체 기본 검사 통과나 기존 제품 변경의 품질 검증 완료를 뜻하지 않는다. 자동 수집·자동 게시·시간 절감·품질 개선 효과는 검증 대상이 아니며 구현·측정하지 않았다. 별도 회귀 테스트를 추가할 업무 동작 변경은 없다.

## 포트폴리오용 요약 초안

AI와 협업한 개발 과정을 포트폴리오 근거로 남기기 위해 사용자 요청과 실제 산출물을 연결하는 기록 절차를 도입했다. 사용자는 기록 목적을 정했고, AI는 작업 양식을 만들고 시작·완료·리뷰 절차에 연결했다. 각 기록에서 사람의 판단과 AI 작업, 검증 결과와 미확인 항목을 구분한다. 수정·추가 문서 11개의 상대 링크 127개를 확인했다. 전체 기본 검사는 다른 변경의 서식 오류로 중단됐으며, 시간 절감이나 품질 향상 효과는 측정하지 않았다.

이 요약은 에이전트가 작성한 초안이며 사용자 검수는 미확인이다.

## 게시 상태

- GitHub Wiki: 미게시. 이번 작업은 하네스 문서 반영이며 원격 게시를 수행하지 않았다.
