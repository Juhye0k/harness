## 요청과 완료 기준

사용자 요청 원문:

> 혹시 main에 아직 반영 안된 작업들이 있으면 모두 반영해줘

원격 main과 각 작업 브랜치·작업 폴더를 비교하고, 미반영 변경을 검토·검증한 뒤 main에 반영한다. 해당 커밋의 원격 CI 결과를 확인한다. 운영 배포·유료 AI·실제 SNS 게시·GitHub Wiki 별도 게시는 이번 요청의 범위가 아니다.

시작 HEAD는 `94f2474a5b971296e0890fe8ecc5d594750fee64`다. 원격 main에는 이 인증·전사 검증 통합 커밋이 없었으며 편집·최종 출력, 로컬 업로드, 추천 수작업 평가와 실패 경로 작업은 미커밋 상태였다. 이전 분할 작업 폴더의 변경 파일에 대응하는 파일이 모두 통합본에 존재함을 확인했다. 오래된 사본으로 최신 코드를 되돌리지 않는다. 기존 stash는 복구용으로 보존한다.

## 구현 범위와 검토

- Google 인증·7일 자료 관리, 전사 복구·자막 검증과 프롬프트/결과 기록 규칙.
- 후보별 불변 자막 편집본, 원음 확인 후 비동기 세로 출력, 클립 SRT와 승인된 출력의 SNS 연결.
- 최대 500MiB·20분 로컬 영상 스트리밍 업로드, 별도 수신 볼륨과 워커 검증·원본 재사용.
- Groq 추천 설정과 원본 ID·시간을 보존하는 입력, 브라우저 수작업 평가.
- 소유자별 분석 요청 receipt, 응답 유실 시 조회 복원, 중복 발행 차단과 합성 장애 검사·격리 워커 종료 하네스.

원본 작업 폴더와 다른 개발 스택을 보존하기 위해 별도 worktree에 고정 사본을 만들었다. 인증·CSRF·사용권, 파일 경로/크기/해시, 중복 선점·비재시도, 삭제 외래키, CI 읽기 권한과 합성 증거 범위를 검토한다. 비밀값·사용자 자료·원본 실행 로그는 게시 대상에 넣지 않는다.

## 검사와 수정

원본 폴더의 기본 검사 375개와 Ruff·서식·Alembic SQL이 통과했다. 고정 사본의 첫 실행은 별도 `.tmp` 상위 폴더가 없어서 134개 setup 오류가 발생했다. 폴더와 기존 로컬 FFmpeg 경로를 준비하고 같은 필수 검사를 다시 실행한다. 업무 assertion은 변경하지 않았다.

고정 사본의 기본 **375개**, 실제 PostgreSQL·Redis·Celery·FFmpeg·Chromium 전체 통합 **106개**, 이후 추가된 실행 중 중복 전달 검사 **1개**가 통과했다. 추가 하네스 범위 단위 **6개**와 최종 Ruff·서식도 통과했다. 앱 SHA-256은 `121a4a613bb9d3e833cee0aae564f7932f0d68f3b51be3e1e672216ffda681b5`다. 이후 변경은 검사·문서이며 앱 소스는 유지했다. 일반/통합 이미지 빌드도 성공했다.

추가 검사 이미지의 전체 재빌드와 첫 격리 강제 종료 실험 중 Docker 연결이 EOF로 끊겼다. 당시 전체 컨테이너가 정지한 상태를 확인했으며 원인을 단정하거나 개발 스택을 임의 재시작하지 않았다. 첫 실험의 `passed=false`, `cleanup=true`를 확인했다. 동일 앱의 검증된 이미지 위에 검사 파일만 복사한 이미지로 추가 회귀를 통과했고 강제 종료 실험은 생성형 격리 프로젝트에서 재확인한다.

검증 중 다른 게시 작업이 인증 커밋과 Google 실계정 검증 문서를 PR #7로 main에 반영했다. 최신 main `fa9496d`의 문서 변경도 병합해 보존한다. 이번 PR은 남은 편집·업로드·추천·실패 경로 변경을 통합한다. 커밋·main 반영·원격 CI 결과는 연결된 PR과 완료 보고에서 확인한다.

## 기여와 한계

사용자는 모든 미반영 작업의 main 통합을 지시했다. AI는 브랜치·작업 폴더 비교, 고정 사본 구성과 코드·비밀값·검사 검토, 필요한 통합 수정과 게시를 담당한다. 실제 모델 품질, 최대 업로드 부하, 운영 HTTPS·백업·사용자 검수는 통합 검사와 별도다. 개발 에이전트의 정확한 모델·사용량·비용·전체 소요 시간은 알 수 없음이다. 종료 커밋과 원격 결과는 완료 시 기록한다.
