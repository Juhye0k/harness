## 조사와 결정

실제 jobs/analysis/SNS 저장소·워커 서비스·편집 화면·기존 통합 검사를 읽었다. 기본 단일 선점·수동 중단 확정·조회 오류·SNS unknown 검사는 이미 있다. 추가 핵심은 접수 후 응답 유실과 실제 워커 종료다.

분석 등록에는 클라이언트 요청 ID 기반 재사용이 없다는 차이를 확인했다. 계획에 사용자 범위의 receipt·입력 해시·상태 재조회 보완을 포함했다. 출력 버전·SNS upload_id로 복원하는 기존 기능을 신규 분석 등록에도 이미 제공한다고 표현하지 않았다.

현재 조기 ACK·자동 재시도 없음 계약을 유지한다. 워커 종료 후 running 잔류를 예상 동작으로 검사하고 실행 중단 확인 후 기존 CLI를 사용한다. SNS는 원격 접수 가능성이 있으므로 관리자 unknown 처리와 기존 세션 조회를 구분했다. 자동 감시·자동 복구는 범위에 넣지 않았다.
