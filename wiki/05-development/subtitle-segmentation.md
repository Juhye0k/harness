# 표시 자막 분할과 SRT — VIDEO-005-SUBTITLES

> 상태: 로컬 통합 검증 완료 / 실제 음성 정렬 품질 미평가 · 기준일: 2026-11-16

[위키 홈](../README.md) · [개발 목차](README.md)

## 사용과 저장 경계

`/recommendations`에서 전사 전용 또는 추천 작업이 성공하면 표시 자막과 SRT 다운로드가 나타난다. 원본 전사는 펼쳐서 별도로 확인한다. SRT 시각은 원본 영상의 시작을 0초로 삼는다. 추천 후보 MP4용 시각 이동·내용 수정·자막 편집·영상 자막 합성은 후속 범위다.

`GET /analyses/{id}/subtitles`는 표시 cues·원본 전사 버전·정책 버전·검토 여부를, `GET /analyses/{id}/subtitles.srt`는 같은 cues의 UTF-8 SRT를 반환한다. 완료 전에는 409이고 전사가 없으면 기존 조회 오류를 따른다. 무음은 빈 cues와 빈 SRT다. GET은 저장된 전사만 읽고 전사 호출·작업 생성·DB 수정을 하지 않는다. 다운로드 실패 시 분석 재접수 없이 다시 내려받을 수 있다.

`transcripts.segments`의 원문·구간 ID·시간을 보존하고 새 Groq 전사에는 검증한 `words: [{text, start_ms, end_ms}]`를 부가 저장한다. 별도 표시 계산에서만 공백을 한 칸으로 정리하고 줄바꿈한다. 비공백 문자·구두점은 교정·추가·삭제하지 않는다. 글자수는 Python 문자열 길이이며 실제 폰트 폭은 아니다. 표시 결과를 편집 버전으로 저장하지 않는다.

표시 버전은 `ko-display-v1`이고 JSON에 정책·원본 전사 버전을 반환하며 SRT 파일명에도 표시 버전을 넣는다. 알고리즘 변경 시 버전을 올리고 재현에는 원본 전사 버전과 표시 버전·정책을 함께 사용한다.

## 단어 시각과 캐시

[Groq 공식 문서](https://console.groq.com/docs/speech-to-text)의 파라미터 표를 2026-11-16 확인했다. `verbose_json`과 `timestamp_granularities[]`의 `word`, `segment`를 함께 요청한다. 모델·한국어·음성 형식·temperature=0·단일 호출·시간 제한은 유지한다. 캐시 버전은 `groq-whisper-large-v3-turbo-ko-mp3-16k-64k-word-segment-v2`다.

단어 응답은 순서대로 원문 비공백 문자와 정확히 일치해야 한다. 누락·추가·순서 변경, 비문자열, 비유한 수·불리언·음수·0길이·겹침·구간 밖 시간은 `MODEL_RESPONSE_INVALID`다. 합당한 반복은 보존한다. 원본 길이·구간 순서는 기존 정규화에서도 검증한다. 단어 배열이 없거나 문장부호가 다르면 추정하지 않고 실패한다. provider_calls 선기록·실패 전사 보존·자동 재시도 없음 계약을 유지한다. Azure의 기존 원시 words 필드는 Groq 정규화 형식으로 오인하지 않는다.

v1 전사는 덮어쓰거나 v2로 취급하지 않는다. 과거 성공한 분석 GET은 해당 버전을 계속 읽는다. 대기 중 v1 작업은 새 워커와 설정이 달라 외부 호출 전 `PROVIDER_CONFIG`로 거절한다. 같은 asset_id로 새 분석을 명시적으로 접수하면 v2 전사를 새로 호출할 수 있으므로 기존 데이터·제공자·예산 승인 범위가 적용된다. 조회로 재전사하지 않는다.

## 분할 초안과 검토 필요

다음은 제품 초안이며 접근성·방송 표준 준수나 실제 가독성 통과를 뜻하지 않는다. 서버 코드의 고정 정책이며 사용자 설정 UI는 없다.

| 항목 | 초안 |
|---|---|
| 줄 길이·줄수 | 공백 포함 20자, 최대 2줄 |
| 표시 시간 | 0.8~6초 |
| 읽기 속도 | 초당 15자 이하 |
| 발화 휴지 | 0.7초 이상이면 분리 |

원 전사 구간 안에서 검증된 단어 시간만 사용한다. 종결 부호(`. ! ? … 。 ！ ？`와 닫는 따옴표·괄호), 발화 휴지, 줄수·글자수·6초 경계에서 묶음을 나눈다. 띄어쓰기 경계로 줄바꿈한다. 시각은 첫 단어 시작부터 마지막 단어 끝까지이고 침묵을 메우거나 단어 내부 시각을 추정하지 않는다. 전사 구간을 합치지 않는다.

단어 시각이 없는 v1·다른 제공자의 전사는 한 구간을 한 자막으로 유지하고 `WORD_TIMESTAMPS_UNAVAILABLE`로 검토 필요를 표시한다. 긴 문장을 균등한 시간으로 쪼개지 않는다.

긴 단어·긴 발화·빠른 말·짧은 문장으로 초안을 만족할 수 없으면 원문과 시간을 보존하고 `review_required=true`로 제공한다. `TEXT_LIMIT`, `DURATION_LIMIT`, `SHORT_DURATION`, `READING_SPEED`, 구간 겹침은 `OVERLAPPING_CUES`다. 웹에는 한국어 사유를 보여주고 SRT에는 원문만 쓴다. SRT의 경고는 JSON·웹에서 확인해야 하며 다운로드 성공은 가독성 품질 통과가 아니다.

## 검사와 제한

[단위 검사](../../tests/unit/test_subtitles.py)는 21초·173자 합성 사례의 무손실 분할, 단어 누락·중복·순서·시간 실패, 한국어 공백·문장부호, 불가능한 제약, v1 fallback, JSON/SRT 일치·읽기 전용을 확인한다. [Groq 대역](../../tests/unit/test_groq_provider.py)은 multipart의 word/segment 동시 전달·단일 실패 호출·v1 거절을 확인한다.

[통합·브라우저 검사](../../tests/integration/test_analysis_flow.py)는 합성 영상과 AI 대역으로 PostgreSQL·Redis·Celery·FFmpeg·Chromium을 거쳐 데이터 보존·표시·SRT·모바일 폭·새로고침 재접수 방지·전사 재사용을 검사한다. 실제 실행 결과는 [현황](../07-governance/status.md)을 확인한다. 다른 작업과 병렬 실행할 때 Compose 프로젝트명뿐 아니라 통합 이미지명도 전용 override로 분리한다.

실제 Groq 호출·사용자 영상 전송은 수행하지 않았다. 음성 인식·단어 정렬·의미 경계·초안 가독성은 승인된 고정 샘플과 사람의 판단으로 별도 평가해야 한다.
