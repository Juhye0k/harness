# 빠른 숏츠 자막과 웹 검증 — SHORTS-001

> 빠른 숏츠에서는 긴 문장을 한꺼번에 보여주기보다 짧게 읽을 수 있어야 합니다. 표시 길이·시간 정책, 불확실한 정렬의 검증 화면과 SRT 차단 기준을 설명합니다.

숏츠 자막은 1줄 중심으로 짧게 바꾸되 최대 2줄을 넘기지 않는다. 단어 시간이 검증된 구간만 빠르게 나누고, 시각이 불확실하면 검토 대상으로 남겨 잘못된 완성본 출력을 막는다.

## 합의한 표시 기준

`shorts-display-v1`은 1~3어절·1줄을 기본으로 한다. 공백·문장부호 포함 줄당 최대 14자, 최대 2줄, 목표 0.6~1.2초, 허용 0.45~1.8초, 최대 15자/초다. 기존 0.8~6초 정책을 조용히 완화하지 않고 별도 버전으로 관리한다. 이는 사용자가 선택한 첫 실험 기준이며 집중도·인기 향상을 검증한 수치가 아니다. 참고 쇼츠는 도구에서 직접 재생하지 못했으므로 사용자가 설명한 어절 중심 전환을 기준으로 삼았다.

단어 토큰이 한 어절의 일부라면 원문 공백 경계까지 합친다. 검증된 실제 시각만 사용하고 1~3어절 후보를 구성해 전체 구간을 빠짐없이 나눌 수 있는 경로를 선택한다. 1줄 후보를 우선하고 인접 어절을 묶어 짧은 표시를 피한다. 0.3초 이상의 발화 휴지를 넘겨 묶지 않는다. 문장부호 경계와 0.9초에 가까운 표시를 선호한다. 원문 수정·생략·어절 내부 임의 분할·균등 시간 배분·시각 연장은 하지 않는다.

조건에 맞는 완전한 분할이 없으면 원 구간 전체를 검수 필요로 반환한다. 따라서 21초·9줄을 정상 숏츠 자막으로 출력하지 않는다. 추가 정렬 모델·유료 호출은 도입하지 않았다.

## API와 출력 계약

- `GET /analyses/{id}/subtitles?profile=shorts-display-v1`: 정상 자막, 미확정 원문·시간·사유, 적용 정책, 커버리지와 품질 판정을 반환한다.
- 같은 profile을 SRT API에 지정하면 품질 미달·미확정 구간이 있는 선택 범위는 `409 SUBTITLE_REVIEW_REQUIRED`로 차단한다. 부분 자막만 정상 완성본으로 내려받지 않는다.
- 범위를 지정하려면 `start_ms`, `end_ms`를 함께 보낸다. 영상 범위를 넘거나 순서가 잘못되면 422, 자막 중간을 자르면 검수 필요다. SRT 시간 기준은 원본 영상이며 임의로 0초로 이동하지 않는다.
- profile을 생략한 기존 API는 `ko-display-v1` 호환 동작을 유지한다. 웹의 표시와 다운로드 링크는 새 profile을 명시한다. 자막 없는 영상 추출 계약은 그대로다.

## 웹 검증과 기록

기존 웹앱의 `/verification?analysis=분석ID`에서 처리 상태, 코드 검사, 실제 표시 품질, 사람의 전사 검토를 각각 보여준다. GET은 DB·기존 파일만 읽고 작업 발행·모델 호출·인코딩을 하지 않는다. 미확정 구간에서 원문 검수 화면과 음성 재생 위치로 이동할 수 있다.

사람의 전사 검토는 기존 버전별 `ok/error` 판정을 기준으로 하며 `uncertain`은 미완료다. 이 상태를 자막 가독성 승인이나 CER 측정으로 취급하지 않는다. 정답 전사가 없으면 CER은 평가 불가다.

`scripts/verify.py --report 경로`는 현재 앱 해시·시각·기본 검사 결과를 JSON으로 쓴다. 실패 시 기본 통과를 기록하지 않고 검사 도중 소스가 변하면 거부한다. 인프라 통합은 별도 실행이며 성공을 확인한 실행 기록만 `integration=true`로 반영한다. API는 `VERIFICATION_RECORD` 또는 영상 데이터 폴더의 `verification-code.json`을 읽는다. 현재 앱 해시와 다르면 이전 결과, 파일이 없거나 잘못되면 미확인으로 표시한다. 검사 숫자를 화면에 하드코딩하지 않는다.

비교 자료는 `python -m app.cli.register_verification_assets --analysis-id ID --source 승인된폴더 --data-dir 데이터폴더`로 명시적으로 등록한다. 기존 파일 덮어쓰기를 거부하고 지정한 PNG·MP4만 복사한다. 서버는 등록된 manifest의 파일만 제공하며 상대 경로 이탈을 거부한다. `.env`, 원시 제공자 응답, 저장소 전체를 웹에 마운트하지 않는다. 이전 정책의 비교 자료는 현재 빠른 정책의 합격 근거와 구분해 표시한다.

## 실제 샘플과 검사

승인된 같은 영상의 전사 121개에 적용한 결과 원 구간 19개에서 정상 자막 60개를 생성했다. 모두 1줄이고 최대 표시 길이는 1.68초다. 나머지 102개 원 구간은 시간 정보 부족 또는 읽을 수 있는 분할 불가능으로 차단됐다. 기존 정렬 복구 22개 중 일부도 새 표시 기준을 만족하지 못해 제외된다. 전체 품질은 미달이며 전체 SRT 다운로드도 차단한다. 이를 전체 자막을 해결한 것으로 표현하지 않는다.

21.483초·9줄, 0.5/0.66초, 어절 내부 토큰, 겹침·비정상 시각·범위 자르기·부분 출력 차단과 기존 정책 호환을 검사한다. 브라우저 검사도 새 기준에 맞게 1~3어절 분할과 다운로드 계약을 확인한다. 기존 72개 자막 API 검사는 유지하고 새 웹의 합성 샘플은 108개 자막으로 기대값을 변경했다. 단순히 실패 assertion을 제거하지 않았다.

최종 검사 결과는 [현황](../07-governance/status.md)에 기록한다. 품질·정답 전사 확인은 일반 CI와 분리하며 원본 영상·전사·실행 로그는 공개 Git/Wiki에 올리지 않는다.

## 최종 실행 근거와 동시 작업

작업 중 다른 기능의 코드·테스트가 같은 폴더에 추가되어 검증 도중 소스 해시가 달라졌다. 이 경우 기본 검사 스크립트가 통과 기록을 거부했다. 다른 작업 파일을 덮어쓰지 않고 별도 스냅샷에 현재 코드를 고정했다. 스냅샷에서 발견된 별도 개발 스크립트의 서식은 복사본에서만 정리했다.

고정 스냅샷은 Ruff·서식·기본 303개·Alembic 오프라인 SQL 및 격리 PostgreSQL·Redis·Celery·FFmpeg·Chromium 통합 63개를 통과했다. 기존 Starlette/httpx 경고 1개는 남는다. 기본/통합 실행은 같은 앱 해시에 연결하며 통합 기록에는 테스트·스크립트·잠금 파일 지문도 남긴다. 전용 테스트 자원은 정리했다.

검증한 앱 이미지 `shortform-harness:shorts-verified`를 개발 API에 반영했다. 워커의 다른 작업을 중단하지 않았고, 검증 기록과 네 파일의 비교 자료만 데이터 볼륨에 등록했다. 개발 API는 현재 스냅샷 기준으로 코드 통과를 표시한다. 이후 작업 폴더에 추가된 미검증 변경을 통과로 표시한 것은 아니다. 직접 확인한 웹 결과는 정상 자막 60개·검수 필요 102개·완성본 링크 숨김·SRT 요청 409이며 원음 시각에 맞는 자막 전환, 모바일 폭과 새로고침 무변경도 확인했다. 외부 AI 호출·정답 판정 대리 입력은 없었다.

이 스냅샷의 API 실행을 재현하려면 기본 Compose에 비공개 실행 기록의 이미지 override를 함께 사용한다. 기본 Compose로 다시 빌드하면 그 시점 작업 폴더의 코드가 반영되므로 코드 해시와 검사 기록을 새로 확인해야 한다. 커밋·원격 반영·Wiki 게시는 별도다.
