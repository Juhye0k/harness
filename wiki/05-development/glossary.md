# 프로젝트 용어집

> 문서에서 사용하는 도구와 작업 용어를 처음 접하는 독자를 위한 사전입니다. API·워커·전사·하네스 등의 의미를 확인한 뒤 관련 설명으로 돌아갈 수 있습니다.

[위키 홈](../README.md) · [카테고리 목차](README.md)


| 용어 | 이 프로젝트에서의 의미 |
|---|---|
| 하네스 | AI와 사람이 작업·검증·수정하도록 구성한 개발 환경과 제어 장치 |
| API | 화면 등 외부 호출자가 서버 기능을 요청하는 인터페이스 |
| broker | 실행할 작업 메시지를 중개하는 구성 요소. 현재 Redis |
| worker | 메시지를 받아 실제 Python 함수를 실행하는 프로세스 |
| task | Celery에 등록해 실행할 수 있는 함수와 그 실행 요청 |
| job | 사용자가 요청한 업무 처리 단위. 현재 데이터 모델은 미구현 |
| ACK | 메시지 수신/처리를 확인하는 신호. 확인 시점은 복구 동작에 영향 |
| result backend | Celery 실행 결과를 저장하는 장소. 현재 진단 테스트에서만 사용 |
| 멱등성 | 같은 요청이 반복돼도 의도하지 않은 추가 효과를 만들지 않는 성질 |
| outbox | 업무 변경과 메시지 발행 예약을 같은 DB 트랜잭션에 기록하는 방식 |
| migration | 테이블 구조 변경을 버전으로 관리하는 절차 |
| JSONB | PostgreSQL에서 JSON 내부 값을 처리·검색하기 위한 자료형 |
| 객체 저장소 | 영상 같은 파일을 키로 저장·조회하는 외부 저장소 |
| 서명 URL | 특정 파일·동작에 제한된 시간 동안 접근하는 주소 |
| 전사 | 음성을 글과 시간 정보로 변환하는 과정 |
| 특징 | 점수 계산의 입력이 되는 음량 변화·움직임 등 분석 값 |
| 렌더링 | 편집 설정을 최종 영상 파일로 만드는 과정 |
| 회귀 검사 | 이미 해결한 문제가 다시 발생하는지 확인하는 검사 |
| liveness | 프로세스가 응답하는지 확인 |
| readiness | 정한 의존성에 연결 가능한지 확인. 현재는 DB·Redis만 해당 |
| CI | 변경이 올라오면 정해진 환경에서 자동 검사하는 절차 |
| ADR | 기술 선택의 배경·대안·결정·결과를 기록한 문서 |

job ID와 Celery task ID, 업무 DB와 result backend를 같은 것으로 생각하지 않는 것이 중요하다. 상세 흐름은 [실행 흐름](../03-architecture/runtime-flows.md)을 참고한다.
