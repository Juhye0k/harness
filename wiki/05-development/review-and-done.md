[위키 홈](../README.md) · [카테고리 목차](README.md)

## 리뷰 목적

검사 통과만으로 확인할 수 없는 범위·실패 처리·운영 영향을 검토한다. 자동 AI 리뷰 서비스는 아직 연결하지 않았으며 현재 에이전트에 diff 검토를 요청하는 방식으로 시작한다.

## 검토 질문

| 영역 | 질문 |
|---|---|
| 범위 | 요청하지 않은 업무 기능·의존성·외부 호출을 추가했는가? |
| 경계 | API에서 긴 작업을 직접 실행하거나 import 시 외부 연결하는가? |
| 실패 | 오류를 성공으로 표시하거나 실패 원인을 감추는가? |
| 데이터 | 소유권·구간·편집 버전·중복 실행을 고려했는가? |
| 정보 | 비밀값·원본 영상·접속 문자열이 응답·로그·커밋에 포함되는가? |
| 검증 | 관련 실패를 잡는가? 기존 assertion을 약화했는가? |
| 운영 | 시간 제한·동시성·비용·복구에 미치는 영향을 설명하는가? |
| 문서 | 계획과 구현 상태가 일치하고 실행 명령이 정확한가? |

## 리뷰 의견 형식

`파일·위치 → 발생 조건 → 영향 → 수정 제안 → 검증 방법`

예: 'ready API에서 예외 문자열을 그대로 반환하면 DB 접속 정보가 노출될 수 있다. 구성 요소 상태만 반환하고 원본 오류가 응답에 없는지 검사한다.' 근거 없이 일반적인 보안 문구만 나열하지 않는다.

## 완료 조건

- 요구 범위를 충족하고 관련 문서를 갱신했다.
- 기본 검사 통과, 관련 통합 검사 결과 또는 미실행 이유를 남겼다.
- 실제로 실행하지 않은 모델·배포·서비스 연결을 완료로 표현하지 않는다.
- 변경 diff에 개인 자료·키·영상·.env가 없다.
- 푸시했다면 해당 커밋의 CI 결과를 확인한다.

AI의 '문제없음' 의견은 테스트나 사람의 검토를 대체하지 않는다. 모델 변경의 추천 품질은 [AI 평가 설계](../02-delivery/phase-04-ai-evaluation.md)로 확인한다.

## PR 설명

[저장소 양식](../../.github/pull_request_template.md)을 사용해 문제·변경·검증·남은 위험을 기술한다. 실패했던 접근을 시간순으로 나열하기보다 최종 동작과 판단 근거를 적는다.
