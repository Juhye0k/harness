# 한국어 자막 포함 세로 영상 샘플 — 출력 1단계

> 편집 기능을 연결하기 전에 한국어 자막이 포함된 세로 영상을 작은 합성 샘플로 확인했습니다. CLI 실행과 클립 기준 시간 변환, 폰트·출력 검사의 계약을 설명합니다.

[위키 홈](../README.md) · [개발 목차](README.md)


## 목적과 범위

`portrait-subtitle-sample-v1`은 고정 합성 영상과 자막으로 최종 출력의 기초를 확인한다. 네트워크·AI·DB·Redis·Celery·SNS를 호출하지 않는다. 실제 사용자 영상·전사·저장된 분석을 읽거나 수정하지 않는다.

`app.cli.render_sample` → `services.portrait_sample` → `adapters.portrait`로 실행한다. 시간 변환·고정 자막 검증과 ASS 작성은 `domain.portrait`에 있다. 기존 추출 CLI·후보당 출력 작업 재사용·자막 API의 시간 기준은 변경하지 않는다.

## 실행

저장소 루트에서 실행한다. Python 3.12·uv·FFmpeg·FFprobe가 필요하다.

```powershell
uv sync --locked
uv run python -m app.cli.render_sample
```

기본 위치는 `.artifacts/portrait-samples/<실행 ID>/`다. 고정 위치가 필요하면 **아직 존재하지 않는 폴더**를 지정한다.

```powershell
uv run python -m app.cli.render_sample --output-dir .artifacts/portrait-samples/my-first-sample
```

기존 폴더는 `OUTPUT_CONFLICT`와 종료 코드 1로 거절한다. 기본 실행을 반복하면 새 ID를 사용한다. 성공 시 종료 코드는 0이다. 처리 실패는 JSON의 오류 코드로 확인하며 원본 합성 영상과 실패 기록은 남기고 완성 MP4·SRT·미리보기는 정리한다.

| 파일 | 용도 |
|---|---|
| `source.mp4` | 640×360·30fps·12초 테스트 패턴과 440Hz 시험음. 실제 발화는 없다. |
| `clip.mp4` | 원본 2~12초의 10초·720×1280 MP4. 자막은 영상 화면에 합성된다. |
| `subtitles.srt` | 같은 고정 자막의 클립 기준 UTF-8 SRT |
| `preview.png` | 출력 4.8초의 두 줄 자막 미리보기 |
| `result.json` | 도구·프로필·폰트 해시·원본/출력 해시·자막 시각·출력 검사 결과 |

결과 파일은 Git 제외 경로에 생성한다. 샘플 음량을 확인하고 재생한다. 이 시험음으로 음성 인식·발화와 자막의 일치 여부를 평가하지 않는다.

## 화면과 시간 계약

- 출력은 720×1280, 정사각형 픽셀, H.264/AAC MP4다. 정사각형 픽셀의 가로 원본을 비율대로 맞추고 중앙에 배치하며 남은 부분은 검은 여백으로 둔다. 원본을 잘라 채우지 않는다.
- 흰 글자·검은 외곽선·고정 하단 위치·46 크기의 기본 스타일 하나다. ASS는 글자 모양과 위치를 담는 내부 합성용 자막 형식이며 사용자가 입력하지 않는다.
- 원본 기준 정수 밀리초를 받아 시작점을 빼서 클립 기준으로 변환한다. 원본 2.5~3.5초의 자막은 출력 0.5~1.5초가 된다. 경계에 걸친 자막을 자동으로 자르거나 균등한 시간으로 나누지 않는다.
- ASS 시간은 10ms 단위다. 현재 고정 자막은 모두 그 경계와 일치한다. 실제 영상 표시 정밀도는 프레임 간격의 영향도 받는다. 임의 편집 시각의 반올림 정책은 편집 단계에서 확정한다.
- 14자·최대 2줄의 고정 평문 자막만 검증한다. ASS 제어용 중괄호·역슬래시와 줄바꿈 등 제어문자는 거절한다. 일반 사용자용 문구 입력 API나 완성 자막 품질 판정이 아니다. 기존 표시 자막 자동 분할·품질 판정은 바꾸지 않는다.
- 기존 원본 기준 SRT API는 유지한다. 이 CLI만 별도 클립 기준 SRT를 만든다.

## 폰트와 실행 환경

Windows에서는 설치된 `Malgun Gothic`, Debian/Ubuntu에서는 `Noto Sans CJK KR`을 사용한다. 폰트 이름·내용 해시를 결과에 기록한다. 폰트를 결과 폴더나 Git에 배포하지 않으며, 합성 중에만 임시 폴더로 복사하고 정리한다. 두 운영체제의 글자 폭·모양이나 출력 파일 해시가 동일하다고 보장하지 않는다.

Linux의 `fonts-noto-cjk` 설치는 한글이 빈 사각형으로 출력되는 일을 막기 위한 실행 의존성이다. Docker runtime과 기본 CI 설치 항목에 추가했으며 Python 의존성·`uv.lock`은 변경하지 않았다. 필수 폰트가 없으면 `FONT_MISSING`, `ass` 필터가 없거나 도구가 실패하면 기존 `TOOL_FAILED`로 실패한다. 필수 도구·폰트 부재를 성공이나 검사 생략으로 처리하지 않는다.

FFmpeg는 인자 배열과 시간 제한으로 실행한다. 자막·폰트는 작업별 임시 폴더의 고정 상대 경로로 참조하고, 하위 프로세스의 작업 디렉터리만 바꾼다. 부모 프로세스의 현재 위치를 바꾸거나 사용자 경로를 필터 문자열에 넣지 않는다. 임시 MP4를 검사한 후 기존 파일을 덮어쓰지 않는 방식으로 공개한다.

## 검사와 남은 단계

```powershell
uv run python -m pytest tests/unit/test_portrait.py tests/media/test_portrait_render.py -q
uv run python scripts/verify.py
```

단위 검사는 시간 이동·원본 데이터 보존·범위 초과·겹침·제어문자·기존 파일 보존·폰트 부재·시간 초과 정리·샘플 실패 정리를 확인한다. 실제 FFmpeg 검사는 해상도·길이 ±0.1초·음성 트랙·전체 디코딩·원본 해시, 자막 전후 프레임, 두 줄의 밝은 픽셀 영역, 구간 시작 위치와 검은 여백을 확인한다. 한글·공백·작은따옴표·대괄호가 있는 폴더도 사용한다.

픽셀 검사는 글자의 의미·발화 정렬·가독성 평가를 대신하지 않는다. 한글이 올바른 모양으로 보이는지는 별도 미리보기 확인으로 기록한다. 실제 실행 결과·초기 실패와 제한은 [작업 기록](harness/records/2026-11-17-subtitle-render-spike.md)을 따른다.

이후 단계는 편집 저장·불변 출력 버전 → 구간별 편집 UI → 비동기 렌더링·중복 처리 → 다운로드·SNS의 해당 출력 버전 연결이다. 이 샘플 CLI의 성공을 위 기능의 구현 완료로 해석하지 않는다. 임의 회전·비정사각형 픽셀·HDR·모든 입력 코덱은 검증 범위 밖이다.

참고: [FFmpeg ass 필터 공식 문서](https://ffmpeg.org/ffmpeg-filters.html#ass), [개발 하네스 검사](harness/verification.md).
