# 구간별 단어 정렬 복구와 경계 실험 — SUB-ALIGN-003

> 일부 구간의 단어 시간 오류 때문에 전체 응답의 정렬 정보를 버리지 않도록 바꿨습니다. 엄격한 구간별 복구와 별도 경계 실험의 결과, 원음 확인이 필요한 한계를 설명합니다.

[위키 홈](../README.md) · [개발 목차](README.md)


## 문제와 설계

한 구간의 단어 정렬 오류 때문에 응답 전체의 단어를 버리던 처리를 구간 단위로 분리했다. 기본 방식은 원문·시간 검증을 완화하지 않는다. 구간 안의 제공자 단어를 원래 순서로 연결했을 때 원문의 비공백 문자·구두점과 정확히 같고, 시간이 구간 안에서 증가하며, 이전 구간에서 사용한 단어와 겹치지 않아야 분할에 사용한다. 일치하지 않는 구간만 `UNALIGNED_WORD_TIMESTAMPS`로 남긴다.

원래 목록의 일부 시각이 뒤로 가더라도 시간 인덱스는 조회에만 사용한다. 구간의 단어를 시간순으로 재배열해 맞추지 않는다. 구간별 실제 검증에서 역행·겹침을 거부한다. 기본 구간의 원문·시작·끝·순서·영상 범위 검증은 기존 정규화가 계속 수행한다.

복구 버전은 `exact-timed-word-match-v1`이다. 제공자 호출 메타데이터에 복구 버전·성공/유지 개수·미사용 단어 개수를 남긴다. 전사 모델과 표시 알고리즘은 바꾸지 않았고 ASR 캐시의 이전 결과를 다시 계산하거나 덮어쓰지 않는다. 저장된 전사의 GET에 새 호출·복구를 추가하지 않았다. 수정 파서는 이후 실제 요청에 적용되지만 이번 검증에서는 새 모델 호출 없이 저장 응답을 재사용했다.

## 같은 영상의 비교 결과

| 항목 | 기존 전체 유지 | 엄격한 구간별 복구 | 최대 250ms 경계 실험 |
|---|---:|---:|---:|
| 원 전사 구간 | 121 | 121 | 121 |
| 단어를 사용할 수 있는 구간 | 0 | 22 | 70 |
| 단어가 불확실해 유지한 구간 | 121 | 99 | 51 |
| 표시 자막 | 121 | 125 | 133 |
| 표시 제약 경고가 있는 자막 | 26 | 23 | 28 |
| 6초 초과 자막 | 5 | 4 | 4 |
| 글자수·줄수 초과 자막 | 22 | 18 | 11 |

자막 개수가 달라 경고 개수만으로 전체 품질 향상을 단정하지 않는다. 최장 자막 21.483초와 최대 9줄 문제는 엄격한 복구 후에도 남는다. 원문·구간 시간은 변경하지 않았으며 사람의 원음 정렬 평가는 미실행이다.

경계 실험은 원문과 정확히 같은 단어 묶음이 시간 창 안에서 하나만 발견될 때 제공자가 반환한 실제 단어 시간을 사용한다. 단어 시간을 자르거나 보간하지 않는다. 표시 계산용 복사본에만 최대 150/250ms의 경계 차이를 허용하고, 원 전사·DB·영상은 보존한다. 영상 범위·단어 재사용·시간 역행·중복 후보는 거부한다. `ko-display-bounded-preview-v1`·`experimental_boundary_preview`로 별도 표시한다.

250ms 실험에서는 일부 긴 자막이 줄었지만 짧은 표시·읽기 속도·겹침 등을 포함한 전체 제약 경고가 늘었다. 따라서 기본 파서는 경계 허용 0ms를 유지하고 실험은 오프라인 CLI에서만 명시적으로 실행한다. 경계 허용은 측정된 정확도나 합격 기준이 아니다.

## 실행과 출력

비공개 폴더에 이미 저장된 응답·전사를 사용한다. 이 명령은 원본과 DB를 수정하지 않고 새 출력 폴더에 JSON·SRT·비교 보고서를 쓴다. 다른 전사의 응답·원문/시간 불일치·기존 출력 덮어쓰기를 거부한다.

```powershell
uv run python -m app.cli.align_subtitles `
  --transcript .artifacts/evaluation-input/transcript.json `
  --response .artifacts/evaluation-input/provider-response.json `
  --duration-ms 404237 `
  --output .artifacts/evaluations/strict-alignment
```

경계 실험은 새 출력 폴더와 `--boundary-tolerance-ms 150` 또는 `250`을 명시한다. 보고서에는 원본·응답 해시, 복구/유지 사유, 사용하지 않은 단어 수, 실제 단어와 원 구간의 경계 차이, 전후 표시 제약, 원음 검증 미실시·외부 호출 0회를 기록한다. 원문 비공백 문자 누락·중복 검사도 수행한다.

## 하네스와 검증

한 구간 오류의 격리, 원문 불변, 단어 재사용 차단, 텍스트 차이, 모호한 반복, 비정상 시각, 실제 단어 시간 보존, 영상 끝과 250ms 상한, 잘못된 입력 연결·덮어쓰기 거부를 회귀 검사에 추가했다. 기본 `scripts/verify.py` 269개, Ruff·서식·Alembic 오프라인 SQL 통과. 실제 저장 응답도 새 파서 → 정규화까지 121개·단어 사용 22개로 검증했다. 초기 구현에서 응답 전체의 단어 시각 순서를 검사해 실제 응답의 일부 역행이 모든 구간을 탈락시키는 문제를 발견했고, 조회 인덱스와 구간 내 원래 순서 검증을 분리한 뒤 해당 실패의 회귀 검사도 추가했다.

Docker 복구 후 PostgreSQL·Redis·Celery·FFmpeg·Linux Chromium 전체 통합 **60개가 통과**했다. 새 PostgreSQL 저장 → HTTP 자막·SRT 검사는 실패 구간의 원문·시간 유지와 다른 구간의 단어 복구·분할이 함께 보존되는 것을 확인한다. 기존 Starlette/httpx 사용 중단 예정 경고 1개는 남는다. 전용 테스트 컨테이너·네트워크·볼륨은 정리했다. 실제 AI·SNS 계정에는 접속하지 않았다.

최초 시도는 공간 부족으로 중단됐다. 복구 후에는 기존 통합 이미지의 의존성을 재사용하고 이 워크트리의 `app/`, `tests/`, `scripts/`를 읽기 전용으로 연결했다. 호스트와 컨테이너의 상대 경로별 파일 내용 해시·파일 수·`uv.lock` 해시를 실행 전에 대조했다. 상대 경로 문자열 순서로 해시를 계산해 Windows/Linux 정렬 차이를 제거했다. 이는 최신 소스의 실제 인프라 통합 검증이며 새 production 이미지 빌드나 운영 배포 검증은 아니다.

위 269개·60개는 개별 워크트리 검증 이력이다. 이후 평가 도구와 함께 현재 작업 폴더에 통합하고 같은 영상의 실제 표시 결과·음성 무음 신호를 평가했다. 원문·시각 범위는 보존했지만 최대 21.483초·9줄과 짧은 표시 문제로 가독성 초안은 미달이다. [실제 품질과 통합 기록](harness/changes/transcript-quality-integration.md)을 따른다.

실제 파형에 근거한 단어 경계 정답 확인, 남은 99개 구간의 복구, 모든 자막의 가독성 통과는 남아 있다. 새로운 음성 정렬기·모델·서비스·의존성을 추가하지 않았다. 시작 코드는 `fb9b793`과 요청 시 미커밋 수정이며 현재 변경도 미커밋이다. 푸시·Wiki 게시 전이다.
