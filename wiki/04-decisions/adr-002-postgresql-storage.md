# ADR-002 — PostgreSQL과 파일 저장 분리

> 상태: PostgreSQL 채택 · 객체 저장소 공급자 미정 · 기준일: 2026-11-15 · 유지관리: 프로젝트 개발자

[위키 홈](../README.md) · [카테고리 목차](README.md)

## 배경과 결정

사용자·프로젝트·편집 버전·작업 결과의 관계를 관리해야 한다. PostgreSQL을 서비스 데이터 기준 저장소로 선택하고, 영상 파일은 후속 객체 저장소에 분리한다. 실험 특징과 버전별 설정은 JSONB 사용을 검토한다.

## 대안 비교

| 대안 | 강점 | 이번 결정 |
|---|---|---|
| MySQL | 관계형 모델·트랜잭션·JSON 지원 | 대등한 대안. PostgreSQL만 가능한 요구는 아님 |
| MongoDB 등 문서형 DB | 문서 단위의 유연한 구조 | 현재 관계·버전 추적에 관계형 모델이 자연스러움 |
| SQLite | 서버 없이 로컬 시작 | 여러 API·워커의 동시 접근을 고려해 서버형 DB 선택 |
| 로컬 영상 파일 | 개발이 간단함 | 워커를 다른 호스트로 옮길 때 공유·복구 부담 |

NoSQL 전체가 관계나 트랜잭션을 지원하지 않는다고 가정하지 않는다. 이번 선택은 데이터 모델과 운영 경계를 기준으로 한다.

## 설계 결과

소유자·상태·구간처럼 제약과 조회가 필요한 항목은 일반 컬럼으로 관리한다. 모든 데이터를 JSONB에 넣지 않는다. 파일의 DB 참조와 실제 저장소 파일 사이 일관성·삭제 순서는 후속 설계가 필요하다.

## 비용과 운영

현재 로컬 Compose DB는 개발용이다. 관리형 DB는 백업·운영 부담을 줄이는 공개 배포 후보이며 아직 구매·배포하지 않았다. 객체 저장소도 S3 호환 방식만 방향으로 정했고 공급자·가격·리전은 미정이다.

## 재검토 조건

실제 쿼리·백업 요구·관리형 비용을 측정한 뒤 검토한다. 조회가 느리다는 이유로 바로 NoSQL을 추가하지 않고 쿼리·인덱스·연결 수부터 확인한다.
