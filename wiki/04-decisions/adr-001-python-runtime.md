# ADR-001 — Python과 FastAPI 선택

> 상태: 채택 · 기준일: 2026-11-15 · 유지관리: 프로젝트 개발자

[위키 홈](../README.md) · [카테고리 목차](README.md)

## 배경

개발자는 Java·Spring 경험이 있다. 선택 기준은 언어 입문 난이도가 아니라 음성·영상·텍스트 특징을 결합해 하이라이트 선정 방식을 실험하는 목표다.

## 결정

분석 코드와 서버를 Python으로 개발하고 HTTP 경계는 FastAPI로 구현한다. API와 Celery 워커는 같은 저장소를 사용한다. 현재 모델이나 영상 분석 기능은 없다.

## 대안

| 대안 | 적합한 상황 | 이번 판단 |
|---|---|---|
| Spring Boot | 외부 AI API·서비스 기능 중심 | 충분히 가능하지만 Python 분석 실험과 연결하려면 경계가 추가될 수 있음 |
| Django | 관리자·통합 웹 기능 중심 | 이번에는 분석 API·작업 처리 중심으로 시작 |
| Flask | 필요한 기능을 직접 조합 | 요청·응답 형식과 API 문서를 함께 다루는 FastAPI 선택 |
| Spring + Python 분리 | 독립 팀·운영 요구가 명확 | 초기에는 배포·계약 관리 부담 증가 |

## 결과와 절충

분석 실험을 같은 언어로 연결할 수 있다. 대신 Python 환경·모델 의존성·메모리 사용을 관리해야 한다. FastAPI의 비동기 기능이 CPU 인코딩을 빠르게 하거나 긴 작업 복구를 해결하지 않으므로 작업자를 분리한다.

FFmpeg의 처리 품질과 속도는 인코딩 설정·하드웨어·입력에 좌우된다. FastAPI가 Spring보다 좋은 영상을 만든다는 의미는 아니다.

## 재검토 조건

분석은 외부 API로 고정되고 서비스 조직·운영 요구가 크게 달라지거나, 별도 GPU 실행 환경이 필요해질 때 경계를 재검토한다. GPU 워커가 필요하다는 이유만으로 HTTP 서버를 추가하지 않는다.
