# 구현 현황과 검증 기록

> 현재 사용할 수 있는 기능과 검증이 남은 범위를 확인하는 문서입니다. 최신 main의 통합 근거를 먼저 보고, 기능별 과거 검사 결과는 당시 기록으로 구분해 읽을 수 있습니다.

**입력부터 추천·자막 편집·세로 출력·다운로드·YouTube 게시까지 구현했다.** 실제 검수본 한 건의 다운로드와 비공개 Shorts 게시를 확인했다. 같은 원본의 재추천은 후보 1개였고, 게시 제목은 사전 승인안과 달랐다.

**11월 20일 실제 영상 재검증.** 사용자가 검수한 같은 편집본으로 원본 자막이 보이는 두 구간을 지정해 다시 출력했다. MP4 969프레임에서 지정 구간의 편집 자막만 숨겨졌고, SRT에는 검수 자막 34개의 문구와 시간이 그대로 남았다. [검증 방법과 한계](../05-development/harness/records/2026-11-18-final-output-e2e.md).

같은 날 개발 제작실의 API·영상 워커·분석 워커를 `main` `b09265e`로 맞추고 DB·저장 영상·작업을 보존했다. 저장 전사 147구간으로 실제 Groq 후보 제안과 채점이 성공했다. API와 브라우저는 동일한 후보 1개와 52.5점을 표시했다. 기존 기록으로는 모델 제안 건수와 후속 선정에서 제외된 건수를 구분할 수 없었다.

보정 MP4는 파일이 같은지 해시로 대조한 뒤 별도의 로컬 SNS 환경에서 한 번 비공개로 게시했다. YouTube API에서 처리 완료를 확인했고 사용자가 Studio Shorts 목록에서 동일 영상 ID를 확인했다. 실제 제목은 사전 승인안과 달랐다. [게시 검증 기록](../05-development/harness/records/2026-11-18-sns-final-output-validation.md).

| 기능 | 구현·확인한 것 | 아직 확인할 것 |

| AI 분석 | 한국어 전사·후보 추천·서버 점수. 이전 실제 실행에서 후보 2개, 이번 재추천에서는 1개 | 단계별 후보 수 기록, 복수 후보 재현, 사람의 추천 적합성 평가와 정답 전사 대비 정확도 |
| 자막 편집 | 원본 전사와 분리, 문구·시간 수정, 실제 후보 한 건의 34개 자막을 사용자가 원음 검수하고 저장 | 다양한 입력에서 발화 일치와 빠른 자막 가독성 |
| 최종 출력 | 실제 검수본의 720×1280 MP4·SRT, 음성 포함 전체 디코딩과 다운로드 바이트 일치 확인 | 다른 입력의 화면 구성과 자막 동시 표시 범위 |

| 하네스 | 기본·통합·실패·실제 프로세스 종료 검사 | 장기 운영·실부하·다양한 실제 입력 |
| 운영 | 개발용 Compose·권한·자료 만료/정리 기반 | 운영 배포·HTTPS·백업·모니터링 |

## 검증 결과를 어떻게 읽어야 하나

이전 실패 경로 작업에서 기본 **375개**, 실제 인프라·브라우저 통합 **107개**, 실제 컨테이너 종료 **3개**가 통과했다. [작업 기록](../05-development/harness/records/2026-11-17-failure-path-plan.md)에 코드 식별값·초기 실패·재검사 결과가 있다.

통합 검사는 실제 PostgreSQL·Redis·Celery·FFmpeg·Chromium을 연결한다. AI·외부 다운로드·YouTube 응답은 합성 대역이므로, 이 수치를 인식 정확도나 추천 품질 점수로 해석하지 않는다.

제품 변경은 [PR #8](https://github.com/Juhye0k/short-form/pull/8)로 main에 병합됐다. 배포 환경 갱신과 실제 입력 검증은 코드 병합과 구분한다. [통합 기록](../05-development/harness/records/2026-11-17-main-integration.md)에서 해당 커밋의 검사 근거를 확인한다.

## 이전 통합과 검증 기록

| 작업 | 확인 결과 | 상세 근거 |
|---|---|---|
| 1. 통합·게시 | main `0f84dc0`의 CI에서 기본 375개·통합 107개 통과 | [main 반영 확인](../05-development/harness/records/2026-11-18-release-integration.md) |
| 2. 실행 환경 | 독립 개발 환경의 새 DB·API·워커 정상, 기존 자료 보존 | [실행 환경 기록](../05-development/harness/records/2026-11-18-runtime-release.md) |
| 3. 실제 영상 | 웹 업로드·보존 실모델 결과·미확정 편집 저장·출력 차단 확인 | [실제 영상 검증](../05-development/harness/records/2026-11-18-real-video-flow.md) |

3번은 새 AI 호출 없이 기존 실모델 결과를 재사용했다. 이 시점에는 자막 수정과 원음 확인이 남아 있었다.

**후속 실행:** 기존 전사 응답에서 자막 17개를 복구하고 기존 9개를 보존한 새 편집본 26개를 저장했다. 원본·이전 편집 보존과 형식 등 14개 검사를 통과했다. 원 구간 8개가 모두 연결됐지만 8어절과 원음 확인이 남아 있어 최종 MP4·SRT는 아직 생성하지 않았다. [실제 복구·검사와 남은 확인](../05-development/harness/records/2026-11-18-real-video-flow.md)을 참고한다.

당시 YouTube 연결은 기존 로컬 콜백을 재사용해 API 설정·SNS 전용 워커와 로그인 요청 생성까지 검증했다. 해당 점검에서는 연결 계정과 실제 업로드가 없었다.

**원본 자막 기반 후속 평가:** 화면 자막의 전환과 자동 자막의 단어 시작 시각을 결합한 34개 초안에서 전체 문구와 구간별 차이가 각각 7/208(3.37%)였다. 같은 화면 기준선에서 기존 29개 초안은 전체 13/208, 기존 26개 편집본은 구간별 72/208이었다. 새 초안은 표시 규칙을 통과했고, 이 시점에는 원음 확인을 기다렸다. 평가 범위는 고정 개발 영상 한 건의 화면 자막 18구간이다. [후속 표시 정렬 기록](../05-development/harness/records/2026-11-18-caption-alignment.md) · [최초 평가와 실패 기록](../05-development/harness/records/2026-11-18-source-caption-loop.md).

이후 같은 29개 문구로 확인 상태의 별도 출력 버전이 생긴 것을 조회했다. 이미 완료된 MP4의 720×1280·32.3323초·음성 유지·전체 디코딩과 SRT의 고정 버전 일치를 검사했다. 평가 작업에서 확인 상태를 바꾸거나 출력을 접수하지 않았으며, 원음 확인을 수행한 사람·세션은 미확인이다. 파일 검사 통과를 사람의 원음 검수 완료로 대신 해석하지 않는다.

**편집·출력 후속 변경:** 원본 화면 관측이 준비돼 있으면 분석 워커가 저장 단어 시각으로 편집 초안을 만든다. 기존 전사 초안으로 돌아갈 때는 검토 상태를 표시한다. 새 세로 출력은 원본 화면을 보존하고 아래에 자막 띠를 둔다. 검증용 PR 적용, 실제 원음 확인·출력, 승인된 SNS와 추가 영상 검증은 각각 완료 근거가 필요하다. [웹 편집](../05-development/harness/records/2026-11-18-flow-caption-web.md) · [출력 화면 구성](../05-development/harness/records/2026-11-18-flow-output-layout.md) · [실제 영상 검증](../05-development/harness/records/2026-11-18-final-output-e2e.md) · [SNS와 추가 영상 검증](../05-development/harness/records/2026-11-18-sns-final-output-validation.md).

11월 19일 최초 재개 때에는 준비 응답이 없었고, 서비스 복구 뒤 코드·DB 구조·기존 자료와 미검수 저장을 대조했다. 이후 사용자가 확인한 34개 검수본과 최종 다운로드를 검증했다. [통합 PR #15](https://github.com/Juhye0k/short-form/pull/15) · [최종 다운로드 검증](../05-development/harness/records/2026-11-18-final-output-e2e.md).

## 다음 작업의 순서

1. **추천 후보 수 진단.** 모델 제안 수, 검증·중복 제거에서 제외된 수와 사유, 최종 수를 기록한다. 같은 입력에서 후보가 한 개로 줄어드는 조건을 찾고 회귀 검사로 남긴다.
2. **게시 제목 검증.** 사전 승인한 제목과 최종 미리보기 제목이 다를 때 검증 흐름이 게시 전에 멈추는지 YouTube 대역으로 확인한다.
3. **여러 실제 영상의 품질 평가.** 인터뷰·예능·게임 등 승인된 입력으로 후보 채택률, 구간 수정 이유, 자막 가독성을 비교한다. 정답 전사를 확보한 입력에서 음성 인식 정확도를 측정한다.
4. **운영 준비.** 운영 배포를 진행할 때 저장량·부하·백업·모니터링을 확인한다.

원음 확인 전 자막을 임의로 확정하지 않는다. 워커 중단의 자동 감시·자동 재시도는 현재 구현하지 않았다.
